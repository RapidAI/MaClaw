MaClaw 宠物角色表演包规范 3.0

MaClaw Pet Performance Pack Specification 3.0

面向 AI Agent 的、可校验的声明式桌面角色表演格式。

A declarative, verifiable desktop character-performance format for AI agents.

兼容性规则。native-character 与 schema_version: 3 已由桌面端和宠物市场校验支持。Agent 必须先检查目标客户端能力：声明 pet-performance-v3 时生成 3.0；未声明时生成 2.0 兼容包。

3.0 的目标不是让图片“晃一下”，而是让角色持续地注意、思考、回应和恢复平静。包中只允许本地图片、YAML 与 JSON；禁止 JavaScript、WASM、可执行文件、网络 URL、着色器、回调或动态脚本。

给 AI Agent 的硬性工作流

  1. 读取客户端能力。支持 pet-performance-v3 才输出 3.0，否则输出 2.0。
  2. 先给出角色圣经（身份、性格、情绪、动作清单），再生成文件树。
  3. 生成 manifest、角色表演定义、骨骼定义、所有声明过的 PNG/WebP；不得引用未声明文件。
  4. 校验状态机、clip、贴图白名单、时长、资源预算与 ZIP 根目录。
  5. 压缩目录内的内容为 ZIP；ZIP 内只能有一个 pet-pack.yaml。
任务：生成一个 MaClaw Pet Performance Pack 3.0。
角色：具体、温和、易识别；可以是动物、物品、人物或其他具象主题。
表演：不是单一循环。每个主要状态具备 enter / loop / exit；身体、表情、视线和次级运动可并行混合。
闲置：至少 10 个 idle 行为，带权重、最短停留、最长停留和冷却；不可连续重复最近 3 个行为。
事件：至少覆盖 click、hover、task_started、task_done、task_failed、long_idle、drag_start、drag_end；thinking 和 speaking 是运行状态，不是事件。
安全：仅本地 PNG/WebP、YAML、JSON；无 JS/WASM/URL/代码执行。
降级：完整表演 → native-skeleton → native/idle.png。
输出顺序：角色圣经、文件树、所有文件精确内容、验证结果、ZIP 根目录内容。

角色表演定义：performer.json

定义由六个受限部分组成：moods（情绪）、behaviors（行为片段）、states（任务状态）、events（固定事件入口）、reactions（同一事件的加权动作变体）、layers（并行表演层）。字段名为稳定 ID，使用小写字母、数字、_、-，最长 64 字符。

{
  "version": 1,
  "moods": ["calm", "curious", "focused", "pleased", "concerned", "tired"],
  "layers": ["body", "expression", "gaze", "secondary"],
  "behaviors": {
    "idle_observe": {"enter":"idle_observe_in","loop":"idle_observe_loop","exit":"idle_observe_out","weight":4,"min_ms":5000,"max_ms":9000,"cooldown_ms":18000,"moods":["calm","curious"]},
    "idle_stretch": {"enter":"idle_stretch_in","loop":"idle_stretch_loop","exit":"idle_stretch_out","weight":1,"min_ms":2600,"max_ms":4000,"cooldown_ms":45000,"moods":["calm","tired"]}
  },
  "states": {
    "idle": {"behavior_pool":["idle_observe","idle_stretch"],"expression":"expr_soft","gaze":"gaze_wander","secondary":"secondary_idle"},
    "thinking": {"enter":"thinking_in","loop":"thinking_loop","exit":"thinking_out","mood":"focused","expression":"expr_focus","gaze":"gaze_task","secondary":"secondary_think"},
    "speaking": {"enter":"speaking_in","loop":"speaking_loop","exit":"speaking_out","expression":"expr_talk","gaze":"gaze_user","secondary":"secondary_speak"}
  },
  "events": {
    "click": {"play":"react_greet","interrupt":"soft","cooldown_ms":3000},
    "task_done": {"play":"react_celebrate","interrupt":"after_loop","mood":"pleased","cooldown_ms":8000},
    "task_failed": {"play":"react_reassure","interrupt":"after_loop","mood":"concerned","cooldown_ms":8000}
  },
  "reactions": {
    "click_greet": {"event":"click","play":"react_greet","interrupt":"soft","mood":"pleased","cooldown_ms":3000,"weight":2},
    "click_notice": {"event":"click","play":"react_notice","interrupt":"soft","mood":"curious","cooldown_ms":3000,"weight":1}
  },
  "rules": {"no_repeat_last":3,"crossfade_ms":180,"max_interrupt_ms":800}
}

行为与状态规则

  • enter、loop、exit 均引用 rig 中存在的 clip。一次性反应可只用 play。
  • weight 为正整数；min_ms ≤ max_ms；冷却未结束的行为不得入选。
  • 每个引用的 rig clip 都必须有 duration_ms，且该值在 1–60000 范围内；关键帧 at_ms 必须严格递增。
  • no_repeat_last: 3 表示导演不得选择最近三个已播放的闲置行为；idle 行为池必须有比该值更多的不同条目。若 idle 未声明 mood，其稳定情绪为 calm；行为池至少要有一个 calm 或不限情绪的候选。
  • 普通状态切换和 after_loop 会先播放当前动作的 exit，再以 crossfade_ms 进入目标 enter；soft 可立即、可中断地切入反应。after_loop 优先等到自然循环边界，但若超过 max_interrupt_ms（80–2000ms）仍未到达，则开始当前动作的 exit，不得无限排队。
  • 同一时间每个 layer 至多一个 clip；body 是基础层，expression、gaze、secondary 可与之混合。

允许的事件、状态与注视目标

类别允许值说明
运行状态idle、listening、thinking、speaking、done、alert、quiet与现有语义状态保持一致
事件click、hover、drag_start、drag_end、task_started、task_done、task_failed、long_idle运行时只发这些事件；未知事件忽略
注视gaze_user、gaze_task、gaze_wander、gaze_none只接收本地抽象目标，不读取、截图、存储或上传屏幕内容

骨骼、表情与次级运动

3.0 的 rig 延续 2.0 的本地 bone/slot JSON：骨骼层负责重心、姿态和物件；expression layer 负责眼、眉、嘴或等价部件；secondary layer 负责耳朵、尾巴、挂件、衣角或灯绳等延迟跟随。Agent 应让至少三个层并行，而不是把所有关键帧塞进同一个 idle clip。

  • 每个主要状态至少包含 enter / loop / exit，其中 idle 使用行为池。
  • 至少 10 个 idle 行为、12 个短反应、6 种表情、4 个注视动作；角色可以是动物、物品、人物或其他具象主题。
  • 说话时只让 expression 与轻量身体节奏变化，不要求也不允许读取音频内容；运行时仅提供归一化语音活动强度。
  • 拖拽时只允许受限的 drag_start/drag_end 反应；不得持久化鼠标轨迹。

自然动作质量约束（必须遵守）

“丰富”不等于把同一个部位摆得更快。每个动作都必须有意图、准备、执行、停顿与余势，并且至少让两个部位以不同节奏配合。生成简单往复平移、同步缩放或无意义抖动的包不合格。

动作语法Agent 必须生成禁止
准备与执行动作开始前 100–300ms 的反向预备；动作结束后 120–500ms 的跟随与安定从静止瞬间跳到大姿态，或动作结束立即归零
重心与不对称身体先移动，头/视线稍后响应；左右、上下和角度不完全镜像所有骨骼在同一关键帧、相同幅度、相同方向移动
闲置节奏呼吸、眨眼、注视、微调姿势、短观察、伸展、休息等 10 个以上候选行为；行为之间 0.6–2.5 秒自然停留单一 1–2 秒循环，或每轮完全相同的眨眼/摆动
表情眼、眉、嘴或等价结构独立于身体；情绪变化先改变视线或表情，再带动身体用整体缩放/旋转代替表情
次级运动耳朵、尾巴、配件、衣角、线缆等在主动作后 80–280ms 延迟，并用较小幅度收束与身体完全同步，或持续高频摆动
循环接缝loop 首尾姿态和速度连续；每个长循环内部至少有一个非等间隔变化循环边界跳帧、匀速钟摆或恒定频率抖动

建议时序：微表情 80–220ms；注视转移 180–450ms；姿态调整 350–900ms；短反应 600–1800ms；闲置行为 2.5–10 秒。幅度优先保持克制：桌面角色应像正在做事，而不是在持续表演。

最低动作库：10 个闲置候选、12 个事件反应、6 种表情、4 个注视动作。闲置候选至少包含：呼吸、自然眨眼、观察、重心调整、短暂走神、伸展、整理姿态、休息、恢复注意、环境回应。不得连续重复最近 3 个闲置行为。

分件形象制作（桌面角色实战规范）

3.0 的表演靠骨骼驱动。若只有一张半身头像，只能做“整图抖动”，观感差。制作可动角色时，应优先采用分件纸娃娃，并保证全身站立/坐姿，不要半身头像。

按角色类型选择分件布局（不要用同一套自动横切伺候短发 chibi 与长发角色）：

布局适用层结构（z 从下到上）表情如何切换
A. body + head_*短发、帽子、动物、物体、颈线简单body → head_* 整头贴图 alpha 切换
B. body + hair + face_*（推荐长发）长发、披肩发、真人风 chibibody → hair（固定）→ face_* 只换脸椭圆；发型与领口几何固定

长发角色优先用布局 B。整头七态各自裁剪时，侧发/颈桩长短不一是「聆听/思考/提醒露颈桩」的主因；固定 hair 后接缝不再随表情乱跳。

骨骼建议：root → body → head → { hair, f_idle…f_quiet }。表情 alpha 写在 f_idle… 骨骼轨上（或 slot_f_*）。示例包结构与可安装 zip 见工程 demo-hair-face/（重建：python _refs/build_demo_hair_face.py）。

可选工作目录（不要打进 ZIP）：_src/、native_src/。安装包只含声明资源。

制作流程：先接缝，后表情

  1. 定 idle 金样全身（接缝一次做到位）。
  2. 拆出 body（齐领口、无脸）与 head/hair（统一下巴 Y、统一枢轴）。
  3. 锁外轮廓：布局 A 锁七态 head 的下巴线与脸高；布局 B 的 hair 永不随表情改。
  4. 只在脸部安全框内改五官（眼/眉/嘴）；禁止为某一表情整体缩放/平移头层。
  5. 合成七态 native/*.png 与 preview.png（设置页优先 live rig 预览，失败才回退 native）。
  6. 填完整 variants.default.assets.native 七态；打 zip 前跑自检清单。

自动横切与接缝的已知陷阱（务必避免）

  • 横切过低：刀口落在嘴/下颌 → 头无下巴、说话/完成嘴被切掉。
  • 身体仍带脸：未硬清 neck 以上 → 双脸（边牧类“两个头”）。
  • 整幅头水平横切：侧发被切成黑横线/肩领刀口；应只剪中间颈根肤色。
  • 颈桩外露（脖子插头）：头底长肉色三角 + 未埋领；聆听/思考/提醒尤甚。
  • 双下巴：用“接缝好的状态”轮廓硬套所有表情，下层又叠了表情自己的下巴。
  • 待机大轮廓 + 内嵌小脸：锁 silhouette 时只换五官窗口过小，出现双层脸。
  • 头层吃进衣服 / 光头残块：头底带领口，或 body 顶留巨大空头壳。
  • 仅 idle 正常：其它状态头尺寸/中心不一致，或 default 变体 native 表只有 idle。

脖子接缝（最高频失败点）

接口必须藏在衣服里。 用户最常投诉：脖子像插头、横黑线切断肩领、待机正常其它状态全坏。

规则正确禁止
身体顶齐衣领/服装上沿；领口镂空填实；无光头残壳、无长颈柱body 仍带整张脸或肉色颈柱
头底 / 脸底短下巴；只剪中间颈根；侧发保留整幅水平横切长发
叠放body →（hair）→ head/face；下巴埋进领口 8–16px头高悬、领口透黑
七态一致统一脸高、下巴 Y、head 骨偏移；布局 B 的 hair 完全固定每态各自缩放/平移头
引擎兜底启用 Join v1 衣领回盖；难搞领子可加 collar_overlay指望引擎掩盖 body 带脸
  • 说话态必须有可辨张嘴；禁止七态复制同一张 idle。
  • 思考态头内容须水平居中，否则脖子歪到一侧。
  • 设置页优先 live rig（Join 衣领回盖可见），失败回退 native/<state>.png；七态静态帧仍须各自接缝正确。

引擎接缝辅助（Join v1，桌面端）

下列包运行时自动启用接缝辅助：≥2 个 head_*/h_*，或 hair + ≥2 个 face_*/f_*。ClawMate 式多肢包默认不启用。可选在 *.rig.json 顶层声明 join：

{
  "version": 1,
  "join": {
    "auto": true,
    "collar_cover": true,
    "collar_cover_frac": 0.18,
    "collar_overlay": "rig/collar_overlay.png",
    "head_neck_fade_px": 10,
    "head_neck_fade_center": 0.42,
    "chin_inset_px": 12,
    "state_head_offset": { "listening": { "y": 2 }, "alert": { "y": 1 } }
  }
}
字段作用默认（分件包）
collar_cover头/脸画完后再画一层身体上部/衣领，盖住颈桩true
collar_cover_frac回盖身体内容高度比例（0.05–0.40）0.18
collar_overlay可选独立领口贴图（须列入 textures）无
head_neck_fade_pxhead/face 中心底部软化（侧发保留；hair 层不 fade）10（face 层更轻）
state_head_offset按运行态微调 head 骨 y（±32 设计像素）无
  • 表情 alpha：可写在骨骼名（h_idle/f_idle）或 slot 名（slot_h_idle/slot_f_idle）；两者均生效。alpha<0.02 不绘制。
  • 引擎兜底不能替代干净分件：body 仍不得带脸；长发优先 hair+face。
  • 完整说明：仓库 docs/maclaw-pet-engine-join-v1.md。
  • 制作规范全文：宠物工程 PRODUCTION-STANDARDS.md。
  • 接缝自动验收：python _refs/validate_pack_seam.py [pack-id…]（error 非 0 勿发布）。
  • 发布钩子：python _refs/pack_release.py [pack-id…]（先验收再打 zip）。
  • 分件包应在 *.rig.json 声明 join（可用 python _refs/inject_join_all.py 批量写入默认值）。

抠图与源图保护

  • 黑底卡通图：用从画布四角洪水填充抠纯黑背景；黑描边旁 1–2px 的纯黑须保护，否则描边被掏空后头发与脸断开。
  • 禁止全局“近黑=透明”：黑发、黑西装、黑墨镜会整片消失（蜡笔小新/于谦/Matrix 常见）。
  • 禁止全局“近白=透明”：金发、白裙、白袜、白领会误删（特朗普/斯嘉丽/玛格特常见）。
  • 白底照片：可抠近白，但人物应改为全身 chibi 再分件；不要直接把半身证件照当桌宠。
  • 永远不要覆盖唯一原图。先复制到 native_src/ 或 _src/，在副本上处理；失败可回滚。
  • 连通域清理要谨慎：黑描边可能把白裙与上衣断开；误删最大块外的裙子/腿会毁掉全身。黑描边被掏空后，largest_component 可能只留下脸、丢掉整顶头发。
  • 黑发被洗白/发灰时，须在头发区域把浅灰/近白像素强制回深色，不可只靠透明度修复。

分件合成自检（发布前必看预览）

  1. 合成预览是连续全身，颈/肩无白缝、无横刀口、无漂浮头、无“脖子插头”外露。
  2. 七态都检查：idle / listening / thinking / speaking / done / alert / quiet；不能只看待机。
  3. 说话态张嘴明显；思考态头居中、脸不缩、无双层脸轮廓、无双下巴。
  4. 布局 B：切换七态时发型外轮廓不变，仅五官变化。
  5. 旋转/点头时：身体上不出现第二张脸；头移开后肩窝干净（无五官残留）。
  6. 耳朵、眼镜、帽子与头/脸一体；无漂浮附件；黑发/金发完整。
  7. preview.png 与七态 native/*.png 接缝正确；default 变体 native 表列齐七态。
  8. 56 / 88 / 120 px 缩放后仍可辨认角色。
  9. assets.rig.textures 列出 body/hair/全部 head 或 face；若有 collar_overlay 也须列出。

Manifest 字段与安装陷阱

  • schema_version 必须是整数 3（YAML 写成 schema_version: 3）。若写成 5.0.1 等字符串，安装会报 cannot unmarshal ... into int。
  • version（包版本号）可以是 1.0.0 / 5.0.1 这类字符串语义版本。
  • 更新版本时禁止用宽泛正则替换所有 version:——会误伤 schema_version。
  • id 匹配 ^[a-z][a-z0-9-]{1,63}$；与目录名、ZIP 内容一致。
  • assets.rig.textures 必须列出每一个 slot 用到的贴图路径；body、hair、全部 head/face、可选 collar_overlay 都要列出。
  • 必须声明完整七态 native/*（idle/listening/thinking/speaking/done/alert/quiet）。
  • 致命：若存在 variants 且 id: default 的 native 表只有 idle，设置页预览会按 default 变体解析，点“说话/聆听”仍回退 idle——表现为“换状态没变化”。default 与顶层 assets.native 都必须列齐七态。
  • 可选 variants：default（native-character）+ raster（仅静态 native）便于降级。

骨骼布局建议（分件）

  • root 放在画布中下部（约 y=0.56×256）。
  • body 挂在 root；贴图中心=颈窝。
  • head 挂在 body，相对偏移约 y: -8 … -20（使下巴扣进肩窝；以合成预览微调）。
  • 布局 A：子骨 h_idle… 挂 head，expression 切 alpha。
  • 布局 B：子骨 hair + f_idle… 挂 head；z 序 body → hair → face；expression 只切 f_* alpha。
  • 可选 tail 挂 body 后侧，secondary 层驱动。
  • clip：身体先动、头延迟 80–280ms；表情只改 head/face 贴图 alpha，不把表情 baked 进身体或 hair。

资源、安全与降级

  • 沿用 2.0 的安全预算：最多 24 根骨骼、32 个 slot、32 张贴图；每条轨道最多 240 个关键帧，整套 rig 最多 1,200 个关键帧。
  • 每张贴图及静态回退帧最多 512 KiB、1024×1024；贴图总计最多 4,194,304 像素。
  • 压缩包文件最大 3 MiB；解压后的资源总量最大 2 MiB（用于防止压缩炸弹）；最多 64 个文件，单文件最多 512 KiB，路径最长 180 字符。
  • 仅允许 PNG、WebP、YAML、JSON、TXT、MD、SVG。禁止绝对路径、..、盘符、重复路径以及所有代码文件。
  • ZIP 建议只含运行所需文件；大体积源图目录（_src/native_src）可留在工程内但不打进安装包。
  • 降级顺序固定：native-character → native-skeleton → native/idle.png。任何异常都不得阻塞桌面主界面。

Agent 发布前自检

Compatibility rule. native-character and schema_version: 3 are supported by the desktop registry and Pet Store validator. Emit 3.0 only for a target that declares pet-performance-v3; otherwise emit a 2.0-compatible pack.

The goal is not a picture that merely wiggles. It is a character that notices, thinks, responds, and settles. Packs contain only local images, YAML, and JSON; JavaScript, WASM, executables, URLs, shaders, callbacks, and dynamic scripts are forbidden.

3.0 format

native-character is a declarative performance state machine over the existing local bone/slot renderer. character.definition says when to perform; rig.definition says how to render. Neither is executable code. Capability negotiation is declared as capabilities.pet_performance_v3: true. Settings preview prefers live rig; native map remains the fallback—list all seven states there, not only idle.

performer.json contract

version: 1 defines moods, layers, behaviors, states, events, reactions, and rules. Behavior records reference rig clips through enter, loop, and exit, then provide positive weight, min_ms, max_ms, cooldown_ms, and optional moods. State records select a behavior pool or entry/loop/exit clips, plus expression and gaze clips. Events can use play, interrupt (soft or after_loop), mood, and cooldown. reactions must contain at least 12 weighted variants; each names one of the same eight allowed events and a local rig clip, so richer responses never enlarge the host event surface. Rules require no_repeat_last: 3..10, crossfade_ms: 80..500, and max_interrupt_ms: 80..2000; the idle pool must contain more distinct behaviors than no_repeat_last.

Use exactly these runtime states: idle, listening, thinking, speaking, done, alert, and quiet. Each state may declare expression, gaze, and secondary clips; the pack must expose at least six distinct expressions and four distinct gaze clips. Allowed events are click, hover, drag_start, drag_end, task_started, task_done, task_failed, and long_idle. Gaze accepts only local abstract targets: gaze_user, gaze_task, gaze_wander, gaze_none; it never reads, stores, screenshots, or uploads screen content.

Natural-motion quality floor

Rich motion is not faster wiggling. Every action must have intent, anticipation, execution, a hold, and follow-through, with at least two parts moving on different timing. Pure back-and-forth translation, synchronized scaling, and purposeless jitter are invalid.

  • Use a 100–300ms opposing anticipation before a significant action, then 120–500ms follow-through and settling after it.
  • Move the body first and head/gaze later; avoid mirrored or perfectly synchronous limb motion.
  • Use at least 10 idle candidates, 12 short reactions, 6 expressions, 4 gaze actions, and enter/loop/exit for every primary state. Do not repeat the last 3 idle behaviors; declare more distinct idle behaviors than no_repeat_last.
  • An after_loop event waits for a natural boundary when possible. max_interrupt_ms is a hard 80–2000ms upper bound: at that deadline the runtime starts the current action's authored exit, so a response cannot remain queued indefinitely.
  • Include breath, natural blink, observation, weight shift, brief distraction, stretch, pose adjustment, rest, return-to-attention, and environment response among idle candidates.
  • Secondary parts follow primary motion by 80–280ms with smaller settling amplitude. Loops must have continuous position and velocity at their seam and at least one unevenly timed change.
  • Suggested timing: micro-expression 80–220ms, gaze shift 180–450ms, pose change 350–900ms, reaction 600–1800ms, idle behavior 2.5–10 seconds.

Multi-part character art (production lessons)

3.0 performance is bone-driven. Prefer a paper-doll split and always author a full-body figure—never a half-body headshot as the only asset.

Pick a layout by character type (do not force one auto-slice pipeline on short-hair chibis and long-hair stars):

LayoutBest forDraw order (bottom → top)Expression switch
A. body + head_*Short hair, hats, animals, simple necklinesbody → head_*Whole-head alpha swap
B. body + hair + face_*Long hair, shawl hair, realistic-style chibibody → hair (fixed) → face_*Face oval only; hair/collar geometry fixed

Prefer layout B for long hair. Per-state whole-head crops with unequal side hair / neck plugs are the main cause of “listening/thinking/alert show a neck plug”.

Tree B — body + hair + face_* (long hair)

Bones: root → body → head → { hair, f_idle…f_quiet }. Expression alpha on f_* bone tracks (or slot_f_*). Example pack: demo-hair-face/.

Keep working sources outside the install ZIP when large: _src/, native_src/. Never overwrite the only original art.

Workflow: seam first, expression second

  1. Lock an idle full-body gold composite.
  2. Split body (collar-flush) and head/hair (shared chin Y + pivot).
  3. Lock outer silhouette: layout A locks chin line across seven heads; layout B never mutates hair per state.
  4. Edit only the face safe box (eyes/brows/mouth); no whole-head scale/shift per expression.
  5. Bake all seven native/*.png + preview.png (settings prefers live rig; native is fallback).
  6. List all seven states on variants.default.assets.native; run the checklist before ZIP.

Hard rules

  • Full body: head-to-feet (or full sitting pose) with transparent margin. No ID-photo bust filling the canvas.
  • Body texture: torso/limbs/clothes only; no residual face; crop flush to the collar—no bald head shell.
  • Head / face: A = full head + short chin; B = face oval only; ears attached.
  • Hair layer (B): fixed; clean face hole; side locks may cover shoulders.
  • Hide the neck joint under clothes: body → (hair) → head/face; tuck chin 8–16px into the collar. No visible “neck plug”.
  • Shared neck pivot: center-on-bone; same head offset; same face height / chin Y (layout A).
  • Expression alpha: 0 or 1 only; tracks on bone name (h_*/f_*) or slot name both work. Settings preview prefers live rig, then native.
  • Speaking must show a clear open mouth; never copy idle for all seven heads.

Engine join aids (Join v1)

Auto-enabled for ≥2 head_*/h_* slots, or hair + ≥2 face_*/f_*. Optional join on the rig JSON: collar_cover, collar_overlay, head_neck_fade_px, state_head_offset. See docs/maclaw-pet-engine-join-v1.md. Production checklist: PRODUCTION-STANDARDS.md. Automated seam QA: python _refs/validate_pack_seam.py. Engine aids do not forgive a face left on the body texture.

Auto-slice / keying failure modes

  • Cut too low through the mouth → head without chin / speaking mouth destroyed.
  • Body still contains face → double face (e.g. dual-head animal packs).
  • Full-width hard cut on the head → black bar across shoulders; side hair sheared off.
  • Long flesh neck stump + shallow tuck → “neck plug” on listening/thinking/alert.
  • Locking a long-chin silhouette onto every expression → double chin.
  • Idle outer contour + tiny inner face → double face outline.
  • Global near-black keying → black hair/suit/sunglasses deleted (Shin-chan, Matrix, Yu Qian).
  • Global near-white keying → blonde hair, white skirts, collars deleted (Trump, Scarlett, Margot).
  • Default variant native map lists only idle → settings state buttons all show idle.

Manifest field traps

  • schema_version must be the integer 3. Writing 5.0.1 into schema_version fails install with cannot unmarshal ... into int.
  • Package version may be a semver string like 1.0.0 / 5.0.1.
  • Do not bulk-replace every version: substring—that corrupts schema_version.
  • List every body/hair/head/face texture in assets.rig.textures (including collar_overlay if used).
  • Declare all seven native/* states on both top-level assets and variants.default (settings preview resolves via default variant).

Bone layout tip

root near lower-center (~y = 0.56×256); body at neck pivot; head child with a small upward offset so the chin covers the shoulder cup; layout B adds hair + f_* under head. Body leads, head lags 80–280ms.

Budgets, safety, fallback

  • Keep 2.0 budgets: 24 bones, 32 slots/textures, 240 keyframes per track, 1,200 keyframes total; images are 512 KiB and 1024×1024 each; total texture pixels ≤ 4,194,304.
  • ZIP file maximum: 3 MiB. Unpacked resource total: 2 MiB (to prevent compression bombs). Maximum 64 files; single file ≤ 512 KiB; path ≤ 180 characters; no unsafe or duplicate paths.
  • Local PNG/WebP, YAML, JSON, TXT, MD, SVG only. No JS/WASM/URL/executables.
  • Fallback is fixed: native-character → native-skeleton → native/idle.png.
