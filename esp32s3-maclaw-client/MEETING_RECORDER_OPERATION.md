# MaClaw Pet 会议录音操作规范

EchoEar-2ST 是 MaClaw GUI/Hub 的会议采集入口，复用 Mobile 的会议录音、续传、转写和文稿库处理链路。设备不会通过远程指令静默开始录音。

## 当前操作

| 设备状态 | 操作 | 结果 |
| --- | --- | --- |
| 待机 | 单击屏幕 | 普通语音命令，录制 6 秒后上传给 Agent |
| 待机 | 双击屏幕 | 立即开始会议录音 |
| 会议录音中 | 单击屏幕 | 停止、保存并上传（推荐） |
| 会议录音中 | 双击或长按 | 同样停止、保存并上传，作为触摸容错 |
| 待机 | 长按约三秒 | 清除 Wi-Fi、配对 token 和网关设置，重启进入配置热点 |

设备只有一个电源键，正常交互以触摸屏为主。会议开始后，任何完整触摸手势都解释为停止，避免用户无法结束录音。

## 屏幕反馈

会议录音界面不是静态“录音中”文字：

- 红色呼吸标记表示麦克风正在采集；
- 中央计时器显示已写入 WAV 的时长；
- 波形显示最终写入或上传的同一份 16 kHz 有符号 PCM；
- 每 128 个样本形成一列真实最小/最大值，共 96 列，覆盖最近约 768 ms；
- 不加入随机扰动、镜像造型或预设动画；安静时接近中线，讲话或拍手时出现真实瞬态；
- 使用两块完整 RGB565 DMA PSRAM framebuffer 整帧切换，避免逐条擦写造成闪烁；
- 底部提示“点屏停止保存”。

## 保存、续传与文稿库

1. 固件将音频以 16 kHz、16-bit、单声道 PCM WAV 流式写入 `/storage/meeting.wav`，不在 RAM 中保存整场会议。
2. 停止时修正 RIFF/WAV 长度，并在 NVS 保存恢复信息。
3. 设备按 Hub 握手返回的 `meetingRecording.basePath`、`chunkSize` 和处理模式上传。
4. 每个分块和完整文件使用 SHA-256 校验；每成功一块即保存 `next_chunk`，断电或断网后从该位置恢复。
5. 后台续传不占用前台交互锁，并在分块边界为新语音请求让出 HTTP。
6. Hub 完成上传后执行转写/纪要，并将结果保存到 Mobile 文稿库；设备收到 `meeting_result` 后显示完成信息。
7. Hub 尚未确认处理前，设备保留本地 WAV；确认成功后才清理恢复文件和元数据。

## 失败与恢复

- 麦克风或存储启动失败：显示“录音失败”，不会伪装成正在录音。
- 上传中断：显示“上传未完成”，本地文件保留，联网后自动续传。
- Hub 上传会话丢失或返回 404：设备创建新会话，并从第 0 块重新上传。
- 重启发现旧录音：后台续传，不覆盖宠物待机界面，也不阻止普通语音录制。
- 存储空间有限；当前固件没有实现文档曾描述的“25 分钟自动分段”，不能依赖该能力。

## 实机验收

- 双击开始后屏幕立即进入计时和真实波形界面；
- 安静、说话、拍手三种输入在右侧产生明显不同的波形并向左滚动；
- 单击能停止，串口出现 `meeting stop requested: gesture=short`；
- WAV 头、样本数、持续时间和 SHA-256 校验通过；
- 断网重启后能续传且不阻止普通语音；
- Hub/GUI 完成处理后，Mobile 文稿库出现对应记录；
- 日志中不能出现触摸任务 watchdog。
