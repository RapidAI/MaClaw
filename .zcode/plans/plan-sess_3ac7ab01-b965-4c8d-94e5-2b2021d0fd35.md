# Bot 任务信息补充与个性化偏好记忆机制实现方案

针对您提出的两大核心需求：
1. **任务信息动态补充**（规划阶段直接合入补充；后台执行阶段智能判断新任务 vs 现有任务补充，若是补充则精准注入运行中任务并报告状态）；
2. **记住用户偏好**（如喜欢多图、排版风格等，常驻生效，让 bot 越用越聪明、越用越灵活）。

以下是完整的架构改动与实施计划：

---

## 一、模块一：规划阶段（Planning Phase）补充信息能力打通

### 1. 核心问题定位
- 当前执行确认门禁（`im_confirmation_gate.go`）已具备初步的修改卡片能力，但在上层任务上下文决策层 `guiapp/im_task_context_adapter.go:102` 中，`hasActiveUnderstanding := false` 被硬编码为 `false`，导致在规划澄清态时，用户补充的输入容易脱离当前任务上下文。

### 2. 具体改造
- **动态感知理解与确认态**：在 `im_task_context_adapter.go` 中，替换硬编码的 `false`，通过检查用户是否处于待确认门禁（`h.confirmationStore.get(userID) != nil`）或活跃规划理解会话，动态赋予 `HasActiveUnderstandingSession: true`。
- **上下文连续性保障**：底层 `corelib/agent/task_context.go` 触发 `TaskContinue`，确保规划期的用户补充文本被可靠承接为当前任务的细化，而不是误判为新任务或归档历史。
- **重算与卡片更新**：在 `im_confirmation_gate.go` 中，用户补充后重新调用理解模型刷新摘要、执行步骤，并向用户重新展示更新后的确认卡片。

---

## 二、模块二：后台执行阶段（In-Flight）智能判定、精准注入与状态报告

### 1. 核心问题定位
- 当前 `im_interrupt_handler.go` 仅针对本地前台 loop，当后台任务（通过 `RemoteSessionManager` 运行的独立 AI Background Task）在跑时，新消息绕过了中断/合并调度；且单槽位 `sessionLoops` 无法支持多任务场景下的精准靶向注入。

### 2. 具体改造
- **后台在行任务感知**：在接收到用户新消息时，检索 `RemoteSessionManager` 中属于该用户/工作区且状态为 `SessionBusy` 的后台 AI 会话。
- **新任务 vs 现有任务补充判定**：
  - 计算新消息与各后台任务描述的向量相似度（Embedding Cosine Similarity）及领域意图；
  - **若高相关**（或判定为修改/补充）：归类为 `ActionMerge`；
  - **若不相关**：判定为新任务（`ActionQueue` 排队或新建任务分支）。
- **精准注入运行中任务**：
  - 在 `guiapp/im_loop_control.go` 中增加基于具体 `*LoopContext` 的注入方法 `InjectSupplementaryToLoop`；
  - 包装优先级前缀（`[用户补充需求——请在当前任务中纳入]`），调用 `loopCtx.TryRequestReplan()`，中断正在等待的非必要阻塞操作，并在下一轮迭代中作为系统/用户输入注入上下文。
- **即时状态回显报告**：
  - 立即向用户发送反馈消息，如：`"收到补充信息，已同步至正在后台执行的任务【{任务标题}】中，正在调整后续执行。"`，并在界面上提供操作确认。

## 三、模块三：用户偏好记忆（多图、排版、越用越聪明）

### 1. 核心问题定位
- 当前 Mem0 在线提取器（`online_extractor.go`）已经提取了 `CategoryPreference`，但在构造 System Prompt 时，`prompt_context.go` 中的常驻静态记忆只捞取了 `CategoryUserFact`（用户信息），把用户的偏好和习惯全过滤掉了；且动态检索被限制在包含“我/偏好”的关键词门禁中。

### 2. 具体改造
- **常驻 System Prompt 增加用户偏好与习惯**：
  - 在 `corelib/memory/prompt_context.go` 中，扩展静态记忆提取，捞取用户活跃、未失效的 `CategoryPreference` 与 `CategoryInstruction`。
  - 在生成的 System Prompt 首部嵌入独立的格式化章节：
    ```markdown
    [用户偏好与交互风格] (请在所有任务和输出中主动遵循):
    - 视觉与排版: 用户偏好图文并茂，遇到架构设计、业务流程、技术对比时，主动使用 Mermaid 流程图、架构图或图表展示。
    - 输出风格: 要点先行，逻辑清晰。
    ```
- **可视化倾向自适应（多图响应）**：
  - 在 `guiapp/im_system_prompt.go` 和 Prompt 指引中，增加系统级感知：一旦用户偏好中存在多图/可视化倾向，在方案阐述、代码解释、调研报告中主动激活绘图工具和 Mermaid 代码块呈现。
- **放宽被动检索限制**：
  - 在 `corelib/memory/lightmem_recall.go` 中降低触发门槛，使偏好相关的上下文在普通提问中也能自适应生效。

   - 验证后台运行任务的相似度匹配、精准定向 `TryRequestReplan` 注入与状态提示；
   - 验证 `StaticMemorySectionForPrompt` 正确输出用户偏好段落，且与旧版 `UserFacts` 兼容；
2. **回归测试**：
   - 运行 `go test ./corelib/memory/...` 和 `go test ./guiapp/...` 相关测试，确保既有逻辑零破坏。
