# DiWorker 产品界面规则草案 v1

## 1. 产品定位

DiWorker 是一个面向办公室工作人员和生产线人员的**数字化员工**，也是用户身边的**数字化同事**。

它不是开发工具，也不是编程平台。本版本不保留编程工具入口，不向普通用户暴露技术概念。

### 实现原则
- 优先复用同级目录 `corelib/` 中已有公共能力
- DiWorker 内不重复实现 `corelib/` 已覆盖的基础模块
- 如果 `corelib/` 中相关能力存在问题，优先修复 `corelib/` 再复用
- 新产生的通用能力优先沉淀到 `corelib/`

### 定位原则
- 像同事一样接任务
- 像员工一样完成工作
- 像助手一样随叫随到
- 输出可以直接使用的结果

### 对外一句话文案
- DiWorker，你的数字化同事
- 把工作交给 DiWorker，快速得到结果
- 会写、会整理、会分析、会跟进

---

## 2. 命名原则

### 产品内核心概念
- Agent / Assistant：**数字化同事**
- Task：**任务**
- History：**历史任务**
- Skill：**会做的事**
- Colleague Profile：**同事名片**
- Template：**常用任务**

### 为什么 skill 叫“会做的事”
“技能”对普通用户太抽象，“会做的事”最直接，用户一看就明白。

例如：
- 写通知
- 做会议纪要
- 整理表格
- 生成周报
- 异常上报
- 质量分析

### 专业描述字段
在同事详情页中可补充：
- 擅长事项
- 适用岗位
- 可输出结果

---

## 3. 关于“它有自己的名字”

DiWorker 不是一个冷冰冰的系统，而是一组有名字、有头像、有描述的数字化同事。

### 展示建议
- Welcome 页以“我的同事”卡片为主视觉
- 每位同事都有自己的名字、头像和一句话介绍
- 用户可以修改同事头像、名字和描述
- 历史任务、任务详情中保留“由 XX 处理”

### 示例
- 你好，我是 **小迪**，今天我帮你处理什么工作？
- 我是你的数字化同事 **阿宁**，表格和数据整理可以交给我。
- 本任务由 **老陈** 完成

### 命名建议
名字应：
- 简短
- 好记
- 有亲和力
- 不要技术化

可选风格：
- 小迪
- 阿宁
- 小周
- 老陈
- 小林

如果产品最终确定一组正式同事名字，界面文案应统一围绕这些同事展开。

### 同事名片建议字段
- 头像
- 名字
- 一句话描述
- 更擅长什么
- 会做的事
- 立即找 TA 帮忙

---

## 4. 一级导航建议

为保证易用，一级导航控制在 4 个：

1. **首页**
2. **找同事**
3. **新建任务**
4. **历史任务**

### 各导航定义
#### 首页
用于快速开始工作。

#### 找同事
查看不同数字化同事和它们“会做的事”。

#### 新建任务
输入需求、上传材料、选择输出，开始处理。

#### 历史任务
方便查看、搜索、继续处理以前做过的任务。

---

## 5. 首页（Welcome 页）布局建议

首页目标：让用户进入后先看到“我的同事”，再快速开始工作。

### 首页首屏结构
1. 欢迎语
2. 我的同事（主视觉卡片区）
3. 常用任务（固定 pin）
4. 最近任务
5. 输入框

### 5.1 欢迎区
建议文案：
- 今天想找哪位同事帮你处理工作？
- 你的数字化同事都已就位
- 选一位同事，或者直接告诉我你的需求

### 5.2 我的同事（主视觉区）
Welcome 页主内容应为不同数字化同事的卡片，而不是功能入口列表。

每张同事卡片展示：
- 头像
- 名字
- 一句话描述
- 更擅长什么
- 会做的事
- 按钮：找 TA 帮忙

用户可操作：
- 更换头像
- 修改名字
- 修改描述

示例：
#### 小迪
你的办公同事
更擅长：通知、纪要、周报、邮件
会做的事：写通知、会议纪要、周报总结、邮件草稿

#### 阿宁
你的数据同事
更擅长：表格整理、数据汇总、图表分析
会做的事：整理表格、汇总数据、生成图表、写分析摘要

#### 老陈
你的生产同事
更擅长：生产日报、交接班、异常汇总
会做的事：生产日报、交接班记录、异常说明、上报摘要

### 5.3 常用任务（Pin 住）
首页保留固定常用任务入口，作为“我的同事”下方的快捷开始区。

建议模块名称：
- **常用任务**

建议默认展示 6~8 个，避免太多。

#### 办公室常用任务
- 写通知
- 会议纪要
- 周报总结
- 月报汇总
- 写邮件
- 制作汇报
- 整理表格
- 数据分析

#### 生产线常用任务
- 异常上报
- 交接班记录
- 生产日报
- 巡检记录整理
- 质量问题说明
- 安全检查记录
- 设备点检汇总

### Pin 规则
- 系统默认 pin 一批高频任务
- 用户可以“固定到首页”
- 支持“加入常用任务”
- 首屏控制在 6~8 个，其他放入“更多”

### 5.4 最近任务
首页显示最近 3~5 条任务，方便继续处理。

字段建议：
- 任务名称
- 由哪位同事处理
- 最后更新时间
- 状态
- 快捷操作：继续处理 / 查看结果

### 5.5 输入区
用于自由描述需求。

输入框提示建议：
- 请告诉我你想完成什么工作
- 例如：整理今天的生产异常，并生成一份汇报摘要

配套功能：
- 选择同事
- 上传附件
- 选择输出格式
- 开始处理

## 6. “找同事”页面建议

重点不是展示专家分类，而是展示不同名字、头像和侧重点的数字化同事。

### 页面目标
- 让用户一眼找到适合自己的同事
- 让用户理解每位同事“更擅长什么”
- 让用户查看每位同事“会做的事”

### 分类建议
- 通用同事
- 办公同事
- 数据同事
- 生产同事
- 质量同事
- 设备同事

### 同事卡片字段
- 头像
- 同事名称
- 一句话介绍
- 更擅长什么
- 会做的事
- 适用岗位
- 立即找 TA 帮忙

### 同事详情页建议
- 头像与名字
- 角色描述
- 更擅长什么
- 会做的事
- 最近常帮你做什么
- 最近处理过的任务

### 示例
#### 小周
- 一句话介绍：你的质量同事
- 更擅长：异常上报、质量分析、整改建议
- 适用岗位：质检员、班组长、工艺员
- 输出：异常说明、原因分析、整改清单

---

## 7. “新建任务”页面建议

目标：简单直接，不让用户理解复杂概念。

### 页面结构
1. 我想做什么
2. 上传材料
3. 选择同事
4. 选择输出
5. 开始处理

### 输出类型示例
- 文档
- 表格
- 汇报摘要
- PPT 大纲
- 邮件草稿
- 纪要
- 异常报告

### 交互原则
- 默认少字段
- 需要专业输入时再展开更多项
- 生产线场景优先支持附件、照片、表单化输入

---

## 8. 历史任务页面建议

这是 DiWorker 的关键页面之一，必须方便查看和搜索。

### 页面名称
- **历史任务**

### 搜索支持
搜索框建议支持：
- 任务名称
- 结果内容
- 上传文件名
- 使用的同事
- 会做的事

### 筛选项
- 全部
- 进行中
- 已完成
- 待确认
- 收藏
- 最近使用

### 每条任务展示字段
- 任务名称
- 使用的数字化同事
- 所属“会做的事”
- 最后更新时间
- 状态

### 快捷操作
- 继续处理
- 查看结果
- 再做一次
- 收藏

### 分组方式建议
- 今天
- 本周
- 本月

## 9. 任务详情页建议

V1 任务详情页以“结果导向”为主，不做复杂技术过程展示。

### 页面结构
1. 任务名称
2. 当前状态
3. 当前数字化同事
4. 输入材料
5. 结果内容
6. 操作区

### 操作区按钮建议
- 继续修改
- 重新生成
- 导出结果
- 复制内容
- 再做一次

### 默认弱化的内容
以下信息不应成为主视觉：
- 技术执行过程
- 工具调用细节
- 模型细节
- 运行日志

---

## 10. 必须隐藏的技术概念

本版本不向普通用户暴露以下概念：
- 编程工具
- CLI
- Session
- MCP
- Provider
- API Endpoint
- Daemon
- Tool Router
- Skill 市场
- 模型切换
- 终端/控制台

原则：
**底层可以保留，界面上不要出现。**

---

## 11. 文案风格规则

整体语气应像“同事之间说话”，不要像后台系统。

### 推荐文案风格
- 我来帮你整理
- 把材料发给我
- 我先给你出个初稿
- 你可以继续让我优化
- 这个结果可以直接导出

### 避免的文案风格
- 执行任务
- 调用技能
- 运行流程
- 调用工具
- 创建编排

---

## 12. V1 产品结论

DiWorker v1 应该是一套：
- 面向办公室工作人员和生产线人员
- 以“数字化同事”为核心心智
- Welcome 页以“我的同事”卡片为主
- 首页可快速进入常用任务
- 历史任务易于查看与搜索
- 保留 Maclaw 底层能力，但对外翻译为“会做的事”
- 客户端只需要配置数字员工中心的 IP（或域名）与端口
- 所有 LLM 和外部 API 请求统一通过数字员工中心转发
- 不保留编程工具入口
- 不暴露复杂技术概念
- 与其配套的服务端系统单独放在 `iWokerCenter/` 目录中维护

最终体验目标：
**用户不用理解系统，只要说出工作，DiWorker 就能接住并完成。**
