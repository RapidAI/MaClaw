# Dynamic Notification System — Requirements

## Overview

设置动态通知系统，Hub 管理员和 HubCenter 管理员可以向用户推送通知消息。通知在 AI 助手面板顶部以闪烁铃铛图标提醒用户，用户点击后查看或忽略。HubCenter 和 Hub 使用同一套协议与 UI。

## Actors

| 角色 | 描述 |
|------|------|
| Hub 管理员 | 在 Hub admin 面板（`hub/web/admin/`）管理本 Hub 下的通知 |
| HubCenter 管理员 | 在 HubCenter admin 面板（`hubcenter/web/admin/`）管理跨 Hub 的通知 |
| 终端用户 | 在 MaClaw GUI 桌面客户端 AI 助手面板中接收和查看通知 |

## Functional Requirements

### FR-1: 通知创建（Hub 管理员）

Hub 管理员可以在 Hub admin 面板中创建通知，指定：
- **标题**（必填，最大 100 字符）
- **内容**（必填，Markdown 格式，最大 2000 字符，客户端渲染为富文本）
- **分类标签**（必填，以下之一）：系统公告 / 功能更新 / 安全告警 / 运维通知 / 自定义
- **受众范围**（必填，以下之一）：
  - 所有用户（本 Hub 下全部注册用户）
  - 指定租户（选择一个或多个 tenant）
  - 指定部门（选择租户组织机构图中的部门/group）
  - 指定用户（按 email 或用户 ID 选择）
- **优先级**（可选）：normal / important / urgent
- **IM 通道推送**（仅 urgent 时可选）：是否同时推送到 IM 通道（飞书/微信/QQ），默认关闭
- **生效时间**（可选）：立即 / 定时发布
- **过期时间**（可选）：过期后不再推送给未读用户

### FR-2: 通知创建（HubCenter 管理员）

HubCenter 管理员可以在 HubCenter admin 面板中创建通知，指定：
- 与 FR-1 相同的标题、内容、优先级、时间字段
- **受众范围**（必填，以下之一）：
  - 整个 Hub（选择一个或多个 Hub 实例，推送给该 Hub 下所有用户）
  - 指定租户（选择某个 Hub 下的某个 tenant）
  - 所有 Hub 的所有用户（全网广播）

### FR-3: 通知推送到客户端

- 通知创建后，通过已有的 Hub WebSocket 长连接实时推送到在线客户端
- 对于推送时不在线的用户，在下次连接 Hub 时拉取未读通知
- HubCenter 级通知通过 HubCenter → Hub API → Hub WebSocket → 客户端的级联链路推送

### FR-4: 客户端通知展示

- AI 助手面板顶部标题栏区域显示铃铛图标 - 有未读通知时，铃铛图标闪烁（动画）+ 显示未读计数小红点（最大显示 10）
- 用户点击铃铛后展开通知列表面板（下拉面板）
- 通知列表显示：分类标签、标题、时间、优先级标识、已读/未读状态
- 支持按分类标签筛选通知
- 点击单条通知可展开查看完整内容（Markdown 渲染）
- 用户可标记单条为已读，或一键"全部已读"
- 客户端最多保留 10 条未读通知，超过时最早的自动归档
- urgent 优先级的通知额外弹出 Toast/Banner 提醒（类似新版本提醒的 UI 模式）

### FR-5: 通知管理（管理员侧）

- 管理员可查看已发送通知的列表（含状态：已发布/已过期/草稿）
- 管理员可撤回未过期的通知（撤回后客户端不再显示）
- 管理员可查看单条通知的送达/已读统计（总推送数、已读数、已读率）

### FR-6: 通知生命周期

- 通知状态：draft → published → expired / revoked
- 已过期或已撤回的通知不再推送给新连接的客户端
- 客户端本地缓存已读状态，避免重复提醒

## Non-Functional Requirements

### NFR-1: 协议统一

Hub 和 HubCenter 使用同一套 WebSocket 消息类型和 HTTP API 协议结构，差异仅在受众范围字段。客户端不区分通知来源是 Hub 还是 HubCenter。

### NFR-2: 性能

- 推送延迟：通知创建后 < 3 秒到达在线客户端
- 客户端拉取未读通知 < 500ms（冷启动时）
- 支持单条通知推送给 10000+ 在线用户（广播场景）

### NFR-3: 可靠性

- 通知持久化到数据库，不因 Hub 重启丢失
- 客户端断线重连后自动同步未读通知
- HubCenter → Hub 推送失败时，Hub 重启后可从 HubCenter 重新拉取

### NFR-4: 安全

- 仅认证的管理员可创建/撤回通知（复用现有 `requireAdmin`/`requireGlobalAdmin` 中间件）
- 客户端通过已认证的 WebSocket 连接接收通知（复用现有 machine auth）
- 通知内容不含可执行代码（XSS 防护）

### NFR-5: 兼容性

- 复用现有 Hub WebSocket `Envelope` 格式（`{type, request_id, ts, machine_id, payload}`）
- 复用现有 Hub admin 面板 UI 风格（tab 导航 + 卡片式布局）
- 复用现有前端事件机制（Wails `EventsEmit`/`EventsOn`）

## User Stories

1. **作为 Hub 管理员**，我想向所有用户发送系统维护公告，这样用户能提前知道维护时间安排。
2. **作为 Hub 管理员**，我想向指定部门发送功能上线通知，这样只有相关部门的人能看到。
3. **作为 HubCenter 管理员**，我想向某个 Hub 下的所有用户发送安全补丁通知，这样该 Hub 的用户能及时更新。
4. **作为终端用户**，我想在 AI 助手面板看到未读通知提醒，这样我不会错过重要公告。
5. **作为终端用户**，我想点击铃铛查看通知详情并标记已读，这样铃铛不再闪烁打扰我。
6. **作为 Hub 管理员**，我想撤回一条已发布但内容有误的通知，这样用户不会看到错误信息。

## Acceptance Criteria

- [ ] Hub admin 面板有"通知管理"tab，可创建/查看/撤回通知
- [ ] HubCenter admin 面板有"通知管理"tab（或在现有 news tab 中扩展），可创建跨 Hub 通知
- [ ] 创建通知后 < 3 秒在线客户端收到推送
- [ ] AI 助手面板顶部出现铃铛图标，有未读时闪烁 + 红点计数
- [ ] 点击铃铛展开通知列表，可查看内容、标记已读
- [ ] 客户端重启后未读通知仍然显示（重连时从 Hub 拉取）
- [ ] urgent 通知弹出 Toast 提醒（类似新版本提醒）
- [ ] 管理员撤回通知后客户端不再显示该通知
- [ ] HubCenter 创建的通知能通过级联推送到达指定 Hub 的客户端

## Resolved Decisions

1. **通知内容格式**：支持 Markdown 渲染（客户端渲染 Markdown，admin 面板提供 Markdown 编辑器）
2. **通知分类标签**：需要。预设分类：系统公告 / 功能更新 / 安全告警 / 运维通知 / 自定义。管理员创建通知时选择分类，客户端可按分类筛选。
3. **"指定部门"数据来源**：Hub / 租户的组织机构图上的部门（即 Hub 已有的组织架构数据，非外部同步）
4. **客户端最大未读保留数**：10 条。超过 10 条时只保留最新的 10 条未读通知，更早的自动标记为已读或归档。
5. **IM 通道推送策略**：
   - 默认仅推送到 GUI 桌面客户端
   - 管理员创建 urgent 级别通知时可选择"同时推送到 IM 通道"（飞书/微信/QQ）
   - IM 推送是管理员的主动选择，不是自动行为
