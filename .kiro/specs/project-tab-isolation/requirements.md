# 任务隔离 Tab + 归档沉淀经验

## 概述

用户点击左侧"最近任务"列表中的某个任务时，在 AI 助手面板中新开一个独立的 Project Tab，该 Tab 拥有独立的对话历史和项目上下文，不被其他任务/项目的知识干扰。同时支持右键"归档"操作——归档后任务不可再继续，但其经验/知识被沉淀到长期记忆中供未来参考。

## 需求

### 需求 1: 点击最近任务 → 新开独立 Project Tab

**用户故事**: 作为用户，我点击左侧最近任务列表中的某个任务时，希望在 AI 助手面板中新开一个独立的 Tab，而不是替换当前对话。

**验收标准**:
- 点击任务列表项后，AI 助手面板新增一个 Tab（类型 `"project"`），Tab 标题为任务名称
- 新 Tab 自动激活（切换到前台）
- 如果该任务的 Tab 已存在，则激活已有 Tab（不重复创建）
- 原有的 local Tab 保持不变，用户可以随时切回
- Project Tab 可关闭（closable=true）

### 需求 2: Project Tab 拥有独立且持久化的对话历史

**用户故事**: 作为用户，我希望每个 Project Tab 有自己独立的对话历史，切换 Tab 时各自的对话不会混在一起，关闭后重新打开能恢复之前的对话。

**验收标准**:
- 每个 Project Tab 有独立的 messages 列表
- 切换 Tab 时保存当前 Tab 的对话状态（messages、scrollTop、inputText）
- 切回时恢复之前的对话状态
- 关闭 Tab 时对话历史持久化到磁盘（`~/.maclaw/data/sessions/{projectPathHash}.json`）
- 重新打开同一任务时，从磁盘恢复之前的对话历史
- 超过 30 天未打开的 session 文件自动清理

### 需求 3: Project Tab 的记忆召回严格按项目隔离

**用户故事**: 作为用户，我希望在某个项目的 Tab 中工作时，AI 只召回该项目相关的知识，不被其他项目的记忆干扰。

**验收标准**:
- Project Tab 发送消息时，后端的 `appendProactiveRecall` 使用该 Tab 绑定的 `projectPath` 进行召回
- `RecallDynamic` 在 Project Tab 场景下使用 strict project mode：只返回 tags 中包含当前 projectPath 的 entry + 通用知识（user_fact、preference 等非 ScopeProject 的 entry）
- 不召回其他项目的 `project_knowledge` 和 `task_artifact`
- `buildMemoryIndex` 在 Project Tab 场景下只展示当前项目相关的类别统计

### 需求 4: Project Tab 首次打开时自动加载项目上下文

**用户故事**: 作为用户，我打开一个项目 Tab 后，希望 AI 立即知道这个项目的背景，不需要我重新描述。

**验收标准**:
- 新建 Project Tab 时，自动从长期记忆中召回该项目的 `task_artifact` 和 `project_knowledge` 条目
- 将项目上下文摘要作为系统消息注入到 Tab 的初始对话中（用户可见）
- 摘要包含：项目名称、最近进展、关键产出物路径
- 如果项目有活跃的工作流状态（如编码工作流进行到 task_breakdown 阶段），在摘要中提示当前阶段

### 需求 5: 右键菜单新增"归档"操作

**用户故事**: 作为用户，我希望对已完成或不再需要继续的任务进行归档，归档后该任务不可再继续，但其经验被保留。

**验收标准**:
- 右键菜单新增"归档"选项（在"重命名"、"置顶"、"移除"之后）
- 归档操作弹出确认对话框："归档后将无法继续此任务，但经验会被保留。确认归档？"
- 用户确认后执行归档

### 需求 6: 归档时沉淀经验到长期记忆

**用户故事**: 作为用户，我希望归档任务时，系统自动提取该任务的关键经验和知识，沉淀到长期记忆中供未来参考。

**验收标准**:
- 归档时，系统从该项目的所有 `task_artifact` 和 `project_knowledge` 条目中提取经验摘要
- 经验摘要包含：任务目标、技术方案、关键决策、遇到的问题和解决方法、最终产出物
- 摘要作为新的 `project_knowledge` 条目保存（category=project_knowledge, tags 包含 "archived_experience" + 原项目路径）
- 摘要的 Scope 设为 ScopeGlobal（全局可召回）——经验的价值在于跨场景复用，BM25/embedding 自然决定何时召回
- 原项目路径保留在 tags 中，方便追溯经验来源

### 需求 7: 归档后的任务在列表中标记为已归档

**用户故事**: 作为用户，我希望能区分活跃任务和已归档任务。

**验收标准**:
- 归档后的任务在列表中显示归档图标（📦）替代原有的书签图标（🔖）
- 归档任务默认不显示在列表中（与"移除"类似的隐藏行为）
- 搜索时可以通过关键词"归档"或 "archived" 找到已归档任务
- 点击已归档任务时，显示只读的经验摘要（不可继续对话）

### 需求 8: 多 Tab 与后端消息处理的接线

**用户故事**: 作为开发者，我需要后端能区分不同 Tab 发来的消息，并为每个 Tab 维护独立的会话状态。

**验收标准**:
- `SendAIAssistantMessage` 接受 `projectPath` 参数（或通过 Tab 绑定的 session 传递）
- 后端为每个 Project Tab 维护独立的 `conversationMemory` session（key = userID + projectPath）
- 工具执行（bash、write_file 等）的工作目录自动切换到 Tab 绑定的 projectPath
- 工作流引擎的状态按 Tab 隔离（不同 Tab 可以有不同的活跃工作流）

### 需求 9: "+" 新建任务——从当前对话 Fork

**用户故事**: 作为用户，我在 AI 助手中正在做某件事，想把它独立成一个可追踪的任务。点击最近任务列表旁的 "+" 按钮，当前对话被 fork 到一个新的 Project Tab 中。

**验收标准**:
- 最近任务搜索面板顶部显示 "+" 新建按钮
- 点击后弹出输入框让用户命名任务（可选，默认用当前对话的第一条用户消息截断作为名称）
- 新建的 Project Tab 继承当前 local Tab 的对话历史（fork，不是移动——local Tab 保持不变）
- 新 Tab 自动激活
- 后端为新 Tab 创建独立的 session（复制当前对话历史到新的 per-project userID）
- 新任务自动出现在最近任务列表中
- 后续在新 Tab 中的对话与 local Tab 完全隔离

### 需求 10: Tab 栏溢出处理

**用户故事**: 作为用户，我可能同时打开多个项目 Tab，希望 Tab 栏不会因为数量多而变得不可用。

**验收标准**:
- Tab 栏采用单行 + 溢出下拉模式（类似 VS Code）
- 可见区域显示最近活跃的 Tab（按最后使用时间排序）
- 超出可见区域的 Tab 通过 "▼ 更多" 按钮展开完整列表
- 下拉列表中显示 Tab 名称 + 关闭按钮
- 最多同时打开 16 个 Project Tab

## 约束

- 最多同时打开 16 个 Project Tab（超出时提示用户关闭不需要的 Tab）
- Project Tab 对话历史持久化到磁盘，重新打开时恢复
- 归档操作不可撤销（但底层 memory entries 不删除，只是标记状态）
- 归档经验提取使用 LLM 摘要（需要 LLM 可用），LLM 不可用时只标记状态不提取经验

## 非功能需求

- Tab 切换延迟 < 100ms（纯前端状态切换，不涉及后端调用）
- 项目上下文加载延迟 < 2s（从长期记忆召回 + 格式化）
- 归档经验提取延迟 < 15s（LLM 摘要调用）
- 对话历史持久化文件单个不超过 2MB（超出时自动 trim 旧消息）
