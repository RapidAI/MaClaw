# MaClaw 桌面宠物 · 全双工伴侣计划

- 日期：2026-10-05（同日修订）
- 状态：待评审
- 对象：桌面端 `guiapp` 浮动宠物（`FloatingAssistantManager`）
- 不在本计划：`iot-agentos` 设备固件。那条线见 `docs/maclaw-companion-duplex-plan.md`

## 1. 目标

宠物从「可拖动的动画、点击打开主窗口」变成可语音对话的桌面伴侣。

1. 语音伴侣开启且宠物可见时，本地听唤醒词 **码卡龙**。
2. 唤醒后的指令由**宠物专有 agent 实例**执行，做完后按播报模式说话。
3. 连续对话模式下，没有任务时可以闲聊。闲聊仍是这一个实例。
4. 宠物不显示，语音伴侣一定关闭：麦释放，唤醒停，播报停，缓冲丢掉，该实例的当前回合取消。

说话的节奏要像旁边有个人，而不是对讲机。唤醒后马上听，不先抢着应一声；用户停顿时不截话；说完把话轮交回去，不追问；超时和告别都不宣布结束。

主窗口助手的会话、停止按钮和手动语音保持独立。

现有默认是文字优先（`pet_conversation_mode=text-first`）。这个计划不把「宠物一显示就开麦」变成新默认。语音伴侣要用户打开 `pet_voice_input_enabled`，并把对话模式设为 `voice-turn` 或 `continuous`。

## 2. 何时听、何时停

显示是总闸，但不是开麦条件。两道都要过。

| 条件 | 麦克风 | 宠物 agent |
|---|---|---|
| 宠物隐藏，或 `pet_enabled=false` | 关闭并释放设备 | 当前回合取消，拒绝新回合 |
| 可见，但是文字优先，或语音输入关闭 | 关闭 | 不启动 |
| 可见且语音伴侣开启，尚未唤醒 | 打开，只跑本地唤醒 | 记忆可加载，不跑模型 |
| `voice-turn`：已唤醒，正在听一句 | 打开 | 这句话结束后跑一轮 |
| `continuous`：对话窗内 | 打开，播报时也听 | 窗内多轮；闲聊回合不带工具 |
| 对话窗空闲超时、用户说结束 | 回到只听唤醒 | 不取消已完成的结果 |
| 隐藏、禁用、退出 | 同第一行 | 同第一行 |

关闭路径必须都走到 `PetCompanionSession.Stop()`：`pet_enabled` 关掉、右键隐藏、`HideFloatingButton`、`RefreshAppearance` 发现已禁用、退出应用。

隐藏取消的是宠物这一轮。主窗口正在跑的任务不动。已经落盘的副作用保留，取消掉的那句不补播，重新显示也不自动续跑。对话记忆留在宠物自己的文件里，下次仍是同一个伴侣，隐藏期间不执行。

`pet_quiet_mode` 只关掉动作音和语音播报，回复改成宠物旁的短文字。安静模式不关麦。只有不显示，或语音伴侣没开，才关全双工。

`pet_continuous_timeout_sec`（缺省 30 秒，允许 5–120）只计算对话窗里**双方都没在说话、也没在执行**的空闲时间。识别、思考、工具执行、播报期间不计时。`voice-turn` 没有对话窗：说完、报完，回到只听唤醒。

## 3. 状态

```
隐藏 / 未开启语音
  → 麦关，agent 不跑

只听唤醒（休息姿态，和「正在录这句话」外观不同）
  → 命中「码卡龙」，或语音模式下点击宠物
  → 立刻进入听音姿态并开始收音
  → 一开口就进入听音姿态，不等识别结束。只喊到名字时，立刻播放缓存的「主人，我在，有什么吩咐？」，同时继续收音。同一句里已经带了吩咐，就直接做，不再问一遍。误唤醒不说话。
听一句
  → 停顿约 0.8–1.2 秒才算说完；中间又开口的，拼回同一句
  → 说完：thinking，进入宠物 agent
  → 唤醒后只有静音：安静回到休息，不问「你说什么」
  → 有声音但没认出字：说一次「没听清」，然后回到休息
思考 / 执行
  → 超过约 1 秒就保持 thinking 姿态
  → 超过约 4 秒才说一次「我看一下」，不报工具名，不反复报进度
  → 隐藏或用户明确说停：声音很快淡出，取消这一轮，不说「我停了」
播报
  → 确认是用户在说话：约 100 毫秒内淡出，姿态回到听
  → 说完不追加「还需要什么吗」
  → voice-turn：回到休息
  → continuous：留下听音姿态，话轮交给用户
对话窗
  → 用户接着说：再听一句（免唤醒），「再短一点」「刚才那个」沿用上一轮
  → 空闲超时，或「再见」「睡觉」：只做收势，不宣布结束
  → 隐藏：全部停止
```

唤醒词就是「码卡龙」。检测在本机完成，音频不落盘、不上传。不要把「马卡龙」或拉丁字母 maclaw 写成必须命中的别名；同音误触发靠阈值和日志收，不靠扩大词表。

全双工只属于 `continuous` 的对话窗，指这四条：

1. 播报时麦克风仍开着。
2. 确认是用户开口后，当前播报在约 100 毫秒内淡出，没说完的音频作废。不把半个字硬说完，也不口头宣布停下。
3. 一句的结束第一版用现有能量 VAD。静音大约 0.8–1.2 秒才收尾，避免把思考中的停顿截成两句。仓库里的 ASR 是整段转写，没有语义端点；语义端点不是这一版的验收条件。
4. 宠物默认不主动开口。闲聊要用户先说。说完就把话轮交回去。

插话只停语音。正在写文件、发消息、跑命令的那一轮，不因为扬声器回声或短促人声就中止。用户明确说停、改口，或宠物被隐藏，才取消执行。回声优先用系统回声消除或播放参考信号；抵消不干净时，播报期间提高 VAD 门限，避免自己的声音被当成插话。

## 4. 专有 agent 实例

宠物不进入主窗口当前会话，也不另写一套工具或第二套 `IMMessageHandler`。现有处理器已经按 `userID` 分开 `sessionLoopState`：各自有锁、`LoopContext`、历史和取消。宠物要的实例就是这条边界，由 `PetCompanionSession` 独占创建和取消。

| | 宠物实例 | 主窗口助手 |
|---|---|---|
| 身份 | `UserID=desktop-pet`，`Platform=pet` | `desktop-user` 及其 `desktop-user:<任务>` |
| 运行时 | 自己的 `sessionLoopState` / `LoopContext` | 面板当前 owner |
| 记忆 | 单独文件，例如 `pet_companion_conversation.json` | `ai_assistant_conversation.json` |
| Actor | `pet-companion` | `main-ai` |
| 取消 | 只取消 `desktop-pet` | 面板上的停止 |
| 人设 | 短句口语，像旁边的人 | 面板里的长回复 |
| 工具 | 同一套实现；见下方策略 | 面板自己的策略 |
| 模型 | 读当前模型配置，不改主会话 | 面板所选模型 |

`desktop-pet` 不能用 `desktop-user` 前缀。`trustedDesktopPrincipal` 会把 `desktop-user:` 收成同一个桌面用户，知识库和会话会串。`runtimeActorFromIMMessage` 今天对未知用户一律返回 `main-ai`，接入时要加宠物分支，否则实例身份是假的。

不要调用 `App.ensureConversationMemory()`。那份记忆是主助手的。

说出来的话遵守这些限制：一两句，先给结果，不把用户的指令复述一遍；没有列表、Markdown、工具名，也不叠道歉。闲聊可以带一点性格，但不把记忆主动抖出来。动作音、提示音和说话不叠在一起，说话时压低动作音。

跟得上刚刚说过的话。对话窗里的「再短一点」「发给他」指上一轮的结果和对象，用户不必把原话再说一遍。这是舒适感的一部分，不是额外功能。

工具策略：

- 查资料、读文件，以及用户已经说清楚的修改，直接做，做完用一句结果交代。
- 删除、外发、执行命令，或者对象含糊（「发给他」但不知道是谁），才用一句口语确认，例如「发给小林？」。好、对、发吧都算答应，不必说「确认」。超时未答应就放下，不改用主窗口弹窗顶替。
- 生成了文档（文稿、报告、表格、幻灯片，或用户明确要的一份长文）之后先停住，只说一句：「发给聊天，还是放进移动文稿库？」截图和其他非文稿文件不问这句。选聊天才调用 IM 发文件；选文稿库才写入移动文稿库。两边都没选、说先留着，或连问两遍仍不清楚，文件留在本机。停下、再见，或问完一段时间没人答，就安静放下，不再追问。问句播出来的回声不算回答。没说清发到哪个聊天时，再问一次「发到哪个聊天？」；说了微信、蓝信、电报或 QQ，就发到那个通道里的聊天。发送或入库失败要说失败，文稿仍留在本机，可再选一次。
- 工具如果只能靠主窗口点确认，宠物说「这步要在主窗口里点一下」并停止，不把未完成的确认写进主会话。
- 闲聊回合不挂工具。像「帮我看一下」这种分不清的话仍挂工具，由这一轮自己决定叫不叫，不另做意图分类器。

长结果放在宠物自己的记录里。右键菜单提供「打开宠物对话」，打开的是 `desktop-pet` 这条记录，不插入主窗口当前标签。`full` 播报过长时，嘴上说摘要，其余留在这条记录里。

| 播报模式 | 指令做完 | 闲聊 |
|---|---|---|
| `summary`（建议默认） | 一句口语结果，不说「任务已完成」 | 完整短回复 |
| `done-only` | 一句结果或失败原因，不只说「做好了」 | 短回复 |
| `full` | 说得下的结论；过长则摘要 | 短回复 |
| `off` | 不说话，宠物旁一行字 | 同左 |

失败用一句人话说明发生了什么。听不清只在「有声音但没认出字」时说一次。误唤醒和纯粹的静音都安静回到休息。安静模式的字出现在宠物旁边，几秒后自己消失，不挡住拖动和点击。

## 5. 和现有代码的接法

复用：

- 显示生命周期：`ShowFloatingButton`、`HideFloatingButton`、`RefreshAppearance`、`DisablePetFromMenu`。
- 外观状态：`idle` / `listening` / `thinking` / `speaking` / `done` / `alert`，经 `SetDesktopPetState` 推到原生窗。
- 设置：`pet_enabled`、`pet_voice_input_enabled`、`pet_conversation_mode`、`pet_readback_mode`、`pet_continuous_timeout_sec`、`pet_quiet_mode`、`pet_auto_retry_on_no_hear`。
- 识别和合成：现有整段 ASR、Silero VAD、`SpeakPlainText`。
- 工具实现目录。不复制工具代码。

`PetCompanionSession` 只由浮动窗管理器持有。

- `Start()` 仅在窗口可见且语音伴侣开启时调用，可重复调用。
- `Stop()` 在每条关闭路径调用，可重复调用。取消 `desktop-pet` 的当前 `LoopContext`，清空音频缓冲，停 TTS。
- 采集在 Go 侧，用用户已选的输入设备，不依赖主窗口 WebView。
- 唤醒前的 PCM 只进关键词检测。
- 播报和宠物回合共用一个代号。代号增加后，这一轮没播完的音频作废。主窗口回合不受影响。

麦克风只有一路。主窗口的按住说话或连续语音一开始，宠物立刻让出设备并暂停唤醒；主窗口放开后，若宠物仍可见且语音伴侣仍开启，再恢复。禁止两路同时采集。这从唤醒词阶段就生效，不拖到体验收尾。

点击：

- 文字优先：保持现在的行为，点击唤起主窗口。
- 语音伴侣开启：点击等于喊一次「码卡龙」，不把主窗口抢到前台。打开主窗口留在右键菜单。

休息时的听唤醒，和正在录这句话，必须是两种看得出来的姿态。用户要能判断现在是不是在录自己的话。隐藏或未开启语音时没有听音态，因为没有采集。界面文案用「不说话 / 说一句就停 / 接着聊」，不把全双工写给用户看。

## 6. 分期

### P0　开关

会话挂到显示、语音开关和隐藏上。`Stop()` 释放设备、清缓冲、停 TTS、取消 `desktop-pet` 回合。

验收：宠物关掉或改回文字优先后，录音设备占用消失；主窗口正在进行的对话不被取消；宠物记忆不写进 `ai_assistant_conversation.json`。

### P1　唤醒

只在语音伴侣开启且可见时加载本地检测，词为「码卡龙」。命中后立刻 `listening` 并开始收音；提示音可以有，但不能挡住第一句。主窗口占用麦克风时宠物让路。

验收：正常音量可唤醒；动作音不误唤醒；隐藏或文字优先时喊名字无反应；与主窗口不同时占用麦克风；唤醒后马上下一句不会被提示音吃掉；没说话时宠物不追问。

### P2　一句指令和报告

唤醒后的一句走现有整段 ASR，进入 `desktop-pet` 实例。删除、外发、命令和含糊对象先用一句口语确认；已经说清的修改直接做。结束时按播报模式说话，状态走 listening → thinking → speaking → done，然后按模式回到休息或把话轮交回用户。

验收：口头短任务不靠主窗口按钮完成，并用一句人话报告结果；这段对话不在主窗口当前标签里；用户已经说清的修改不再追问一次；删除、外发、命令未经口头答应不会执行；失败有口头原因；执行超过 30 秒不会被空闲超时砍掉；思考超过约 4 秒会有一次「我看一下」，而不是沉默或播报工具名。

### P3　连续对话

对话窗内免唤醒。播报时保持采集，确认插话后停播，但不因回声中止已开始的写操作。明确的闲聊不挂工具。

验收：播到一半被打断后，后半句不再播出，也不会说「我停了」；接着说「再短一点」能接上上一轮；说完不再追问；超时和告别只有收势、没有结束语；闲聊不改文件、不发消息；隐藏立即停麦、停声、取消宠物回合。

### P4　收尾

安静模式的文字气泡、语音模式下点击即唤醒、误唤醒和首字延迟日志。

## 7. 不做

- 不接 ESP32 固件，也不在本计划里做设备端回声消除。
- 宠物不显示时不监听，不为了下一次唤醒留着麦。
- 不把文字优先改成默认开麦。
- 不主动搭话。
- 不替换主窗口的手动语音按钮。
- 不新建第二套消息处理器，也不把宠物回合写进主窗口当前会话。
- 不引入端到端语音大模型，也不把语义端点当作这一版的门槛。

## 8. 风险

| 风险 | 处理 |
|---|---|
| TTS 被麦拾回，连环触发 | 回声消除；否则提高播报期门限。未确认是用户说话前，不新开一轮，也不取消正在执行的工具 |
| 唤醒词同音过多 | 词表只保留「码卡龙」；用日志收紧阈值 |
| 口头误听导致删除、外发或执行命令 | 只有这几类，或对象含糊时，才在对话窗里用一句口语确认 |
| 唤醒没反应、停顿被截断、做完还追问 | 一开口就听；只喊名字时播放缓存的「主人，我在，有什么吩咐？」；静音 0.8–1.2 秒再收尾；说完把话轮交回；误唤醒不说话 |
| 隐藏后用户以为还在听 | 取消宠物回合并停声；主窗口任务继续 |
| 两路抢同一只麦克风 | 主窗口语音优先，宠物让路，结束后再恢复 |
| 身份串到主助手 | `desktop-pet` 不用 `desktop-user` 前缀；单独记忆文件；actor 必须是 `pet-companion` |
