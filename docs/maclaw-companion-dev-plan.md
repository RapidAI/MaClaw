# 第二部分　开发计划

## 1. 目标与非目标

### 1.1 目标

| 维度 | 目标 |
|---|---|
| 交互形态 | 从 L1（唤醒词 + 整包轮次）升级到 **L3 全双工**：持续音频流上行、语义端点、随时可打断、服务端可主动开口 |
| 响应延迟 | 端到端（用户说完 → 设备出声）**P50 ≤ 1.2 s，P95 ≤ 1.8 s** |
| 伴侣属性 | 有本地状态（情绪/能量/注意力）、有好感度成长、会主动关怀、断网不失能 |
| 可靠性 | 支持 OTA 并具备签名校验与超时回滚 |

### 1.2 非目标（明确不做）

- **不做 L4 端到端语音到语音**（Moshi / GPT-4o Realtime 风格）。仅保留技术跟踪。
- **不做设备端 LLM / 端侧大模型**。ESP32-S3 不承担推理。
- **不做多设备协同与多用户账户体系**。但协议层预留 `user_id` 字段（T2-4）。
- **不重写渲染架构**。条带化渲染仅在新 pet 资源链路上应用，不动现有两份渲染器。

## 2. 现状基线（验收起点）

| 指标 | 当前值 | 来源 |
|---|---|---|
| 交互模式 | L1：唤醒词 → 整包 WAV 上传 → 整包 TTS 播放 | `gateway_dispatcher.c:345` 长轮询 |
| 音频上行 | 16 kHz PCM 整包 WAV，无压缩 | `audio_service.h:43` |
| AEC / VAD | 无 AFE/AEC，仅能量门限；`audio_arbitration_service.c` 处于 SHADOW | grep 确认全仓库无 AFE 调用 |
| 下行通道 | HTTP 长轮询 `outgoing?limit=1&timeout=`，服务端无法主动推 | 同上 |
| OTA | 无（仅元数据提醒，需连电脑刷机） | `update_service.h` 头部声明 |
| pet 状态 | 服务端下发字符串，设备无本地状态机 | `ambient_service.h` |
| 端到端延迟 | **未测量**（无打点） | — |

> **基线未测量是当前最大的盲区。** T0-2 完成前，本计划所有延迟类验收标准都无法判定。

## 5. 依赖与排期约束

```
T0-1 角色设定 ──┬── 阻塞 全部 B 类（T3-*）
                └── 阻塞 T0-4 唤醒词决策
T0-2 打点 ────────── 阻塞 所有延迟类验收（T1-3/T2-3/T4-9）
T0-4 唤醒词决策 ───── 阻塞 T1-2、T1-3 定稿

T1-1 AEC spike ── 阻塞 T1-2 ── 阻塞 T1-3/T1-5
T1-4 世代号 ───── 阻塞 T1-3、T2-1
T2-1 WS ───────── 阻塞 T2-2/T2-3/T2-4
T2-3 流式 TTS ─── 阻塞 T2-4 主动 turn（无流式下行则主动开口体验不可用）
T2-4 ──────────── 阻塞 T3-4 主动关怀
T4-1 缓存配额 ─── 阻塞 T4-2 分区表（16MB 已用满，无空间则无法加 ota 分区）
```

**三条硬约束：**

1. **T1-1 是 go/no-go 闸门。** AFE 的 RAM/CPU 若超出 ESP32-S3 余量，阶段一之后的排期全部作废重估。不要跳过 spike 直接排产。
2. **T4-1 必须先于 T4-2。** 当前 `partitions.csv` 16MB 已用满（factory 3.6MB / model 3MB / storage 9.3MB），不先压缩 `storage` 就没有第二个 app 分区的空间。
3. **T4-2 的首次分发必须走迁移刷机。** 老设备分区表不兼容，无法 OTA 升级到新分区表，需在发布说明中明确告知用户。

## 6. 风险登记册

| # | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| V1 | **AFE + Opus + MP3 + TLS + 渲染算力/内存超限**（ESP32-S3 双核 + PSRAM 已被 Wi-Fi/模型占用） | 阶段一失败，整体重估 | 中高 | T1-1 spike 实测；降级预案：降 Opus 码率、单声道 AFE、必要时放弃常开麦退回"按键说话" |
