# LLM 服务卡与点卡权益生效规则

## 背景

当前服务卡按 `starts_at` 到 `expires_at` 的固定时间窗生效。用户连续兑换多张卡时，后一张卡会排到前一张卡到期后才开始。如果前一张卡提前用完，后一张卡虽然已经在账户里，但还没到 `starts_at`，会导致用户充值后仍然不能使用。

另一个问题是包月卡触发周期限额后，系统不应把账户整体判为不可用。周期限额只限制这张包月卡，本账户内其它可用点卡、兑换卡或余额应继续作为兜底额度。

## 规则目标

1. 用户已充值且有可用额度时，不因为排队开始时间被卡住。
2. 包月卡周期限额只阻塞包月卡本身，不阻塞其它点卡。
3. 包月卡有效期按购买周期顺延，不因某周期额度用完而清零。
4. 额度型卡用完后不再贡献可用额度和最长有效期。
5. 系统展示仍保留原始授权明细，实际扣费时允许必要的提前接续。
6. 无周期限制的无限授权优先级最高；存在此类有效授权时，不再消耗点卡或普通额度卡。

## 权益类型

### 额度型权益

点卡、普通兑换卡属于额度型权益。

- 有 `credits_total`。
- 扣到 `credits_used >= credits_total` 后状态为 `exhausted`。
- 用完后不再贡献 `credits_available`。
- 用完后不再贡献 `effective_expires_at`。
- 如果前一张额度型权益已用完，下一张排队权益可以提前接续。

### 周期型权益

包月卡、周卡、年卡这类设置了 `period_limits` 的服务卡属于周期型权益。

- 有总体有效期：`starts_at ~ expires_at`。
- 有周期额度：如 5 小时、日、周、月限额。
- 当前周期用完时状态为 `period_limited`。
- `period_limited` 只代表这张权益当前周期不可扣，不代表账户不可用。
- 周期重置后恢复使用。
- 同类包月权益默认不因单周期限额提前启用下一张包月卡，避免误消耗多张包月权益。

### 无限授权

管理员授权或特殊权益可能没有 `credits_total`。

- 没有 `credits_total` 且没有 `period_limits`：视为无周期限制的无限授权。
- 无周期限制的无限授权有效时，请求直接通过，不扣其它点卡。
- 当前权益全部因 `exhausted` 阻塞时，下一张排队的无周期限制无限授权可以提前接续，并保持原授权时长。
- 当前权益因 `period_limited` 阻塞时，不提前启用排队的无周期限制无限授权，优先继续使用可扣费点卡兜底。
- 没有 `credits_total` 但有 `period_limits`：视为周期型无限授权，只在当前周期额度内可用。
- 周期型无限授权触发 `period_limited` 后，可以继续走其它可用点卡兜底。

## 接续规则

同一用户、同一服务组下，扣费时按以下顺序找可扣额度：

1. 当前时间内 active 且有可用周期额度的权益。
2. 若存在无周期限制的无限授权，请求直接通过，不扣任何额度型权益。
3. 若当前权益全部因为 `exhausted` 阻塞，允许下一张未生效权益提前接续。
4. 若当前权益因为 `period_limited` 阻塞，只允许无周期限制的点卡/普通额度卡提前接续。
5. 提前接续时保持原卡时长不变：`new_expires_at = now + (old_expires_at - old_starts_at)`。
6. 实际扣费发生时，持久化新 `starts_at/expires_at`，避免后续请求看到不同状态。

## 有效期规则

账户最长有效期来自仍有效权益的最大 `expires_at`。

- 额度型权益：剩余额度大于 0 且未过期才贡献有效期。
- 周期型权益：未过期且有整体权益时贡献有效期；当前周期限额不清零有效期。
- 已耗尽额度型权益不贡献有效期。
- 已过期权益不贡献有效期。

## 扣费结果

当包月卡触发周期限额且点卡可用时：

- 请求继续成功。
- 包月卡状态保持 `period_limited`。
- 点卡被提前接续并扣费。
- 周期重置后包月卡再次可作为优先候选。

当当前卡耗尽且下一张卡已排队时：

- 下一张卡提前从当前请求时间开始。
- 有效期按原时长顺延。
- 本次请求直接扣下一张卡。
