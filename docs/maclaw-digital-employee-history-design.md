# Maclaw 数字员工历史会话设计

## 背景

这是 Maclaw 自身的数字员工能力，与 iWorker / iWorkerCenter 无关。HubCenter 负责 Hub 的数字员工授权，Hub 负责权威会话、数字员工注册管理与审查入口，Maclaw 客户端负责 GUI / TUI / maclawsrv 的本地呈现、缓存和执行。

## 入口显示规则

Maclaw 客户端中间面板显示“最近任务 / 数字员工 / 历史会话”。当任一条件成立时，客户端不显示“数字员工”和“历史会话”两个 tab：

- HubCenter 下发的数字员工授权数为 0。
- 当前客户端实际数字员工数量为 0。
- HubCenter 禁用该 Hub 的数字员工授权。
- 数字员工按年订阅已过期。

授权状态通过心跳同步到 Maclaw 客户端，包括 GUI、TUI 和 maclawsrv。HubCenter 对 Hub 的数字员工授权数只允许变大，续期可以保持原数量并更新有效期。禁用授权只改变授权状态，不清零、不减少既有授权数。

设置页中的“数字员工”设置 tab 与中间面板不同：只要授权处于 active 且 quota > 0，就应保留设置入口，方便用户注册或配置本机数字员工。

## 会话关系

历史会话区分两类本地关系：

- `initiated_by_me`：由当前人类用户在本地 Maclaw 发起。只要会话仍处于 `open` 状态，就可以继续讨论。
- `owned_ve_invited`：当前用户拥有的数字员工被其他讨论邀请参加。对当前用户只读，只能审查内容和下载附件，不能继续发言。

纯咨询类讨论可以没有本地数字员工参与；如果是本地用户发起，也仍然属于 `initiated_by_me`。

## 存储

Hub 是会话权威来源，Maclaw 本地保存同步缓存：

- 会话摘要、消息、参与者、只读状态和本地关系保存到本地数据库。
- 会话内容权威数据保存于 Hub 数据库。
- 附件下载后保存到 Maclaw 数据目录：`group-discussions/{discussion_id}/attachments/`。
- 附件即使来自 `owned_ve_invited` 只读会话，也允许下载，便于人类审查。

本地隐藏不等于删除。`owned_ve_invited` 会话可以本地隐藏并恢复，避免误删审查线索。

## 打开历史会话

历史会话列表项需要清晰标明来源：

- 我发起的会话使用“我发起”图标或标记。
- 我的数字员工被邀请的会话使用“受邀”图标或标记。

双击列表项，或通过右键菜单“打开会话”，会在 AI 助手面板创建新的历史会话 tab。只读会话的 tab 标题必须标明“只读”。

## 继续讨论与只读

客户端根据 `readonly` 和 `local_relation` 决定输入区状态。后端也必须拒绝只读会话的继续发送请求，避免绕过 UI 后写入。

“后端拒绝继续发送”的含义是：对于 `owned_ve_invited` 或已归档/结束的会话，即使客户端误发了继续讨论请求，Hub/Maclaw 后端也返回错误，不写入新消息。

归档表示讨论结束。归档后会话只读，不能继续讨论。

## 附件访问

Hub 上的数字员工附件中转必须满足以下规则：

- 上传和下载都需要机器认证。
- `participant_id` 必须与当前认证机器一致。
- 上传者必须是对应讨论的参与者。
- 下载者必须是对应讨论的参与者；仅知道 `session_id` 和文件地址不能下载。
- 新文件链接使用 `/api/ve/files/download/{id}`，避免与 `/api/ve/{id}/history` 等数字员工管理路由冲突。
- 客户端对旧链接 `/api/ve/files/{id}` 做兼容迁移，但不得把 `/api/ve/files/upload` 当作下载地址。
- 本地已下载附件如果文件仍存在，可直接复用；文件丢失时重新下载。

## 归档与清除

建议的清除策略：

- 管理员可以按合规要求清除 Hub 上的历史会话及附件。
- 发起方是否能清除由管理员策略控制；默认建议发起方只能归档和本地隐藏，不能永久清除 Hub 权威记录。
- 普通审查者和数字员工所有者只能本地隐藏，不能清除 Hub 权威记录。
- 清除应采用审计化流程：记录清除人、时间、范围和原因。
- 可配置保留期，例如 1 年、3 年、永久保留，过期后由管理员批量清理。

## Hub 管理端

Hub 管理端的数字员工管理需要支持：

- 列出数字员工，展示名称、所属邮箱、状态和授权占用。
- 按数字员工名称或注册邮箱搜索历史会话。
- 对搜索结果做简单预览，弹窗展示参与者、状态、最近消息、结果摘要和附件元数据。

Hub 管理端是审查入口，不承担继续讨论。

## 敏感信息查询

数字员工回复过程中如果需要查询密码或敏感信息，按 Maclaw 设置中的“密码或敏感信息查询”安全选项处理：

- `人工确认`：默认值。弹出确认对话框，显示要查询的密码或敏感信息名称，等待 1 分钟；等待期间回复“正在寻求人类员工许可...”；超时默认拒绝。
- `拒绝`：直接拒绝提供。
- `自动允许`：在允许范围内自动提供。

该策略应由本地 Maclaw 执行，Hub 不应直接获得本地密码库访问权。

## 上下文恢复

用户不需要理解“恢复数字员工上下文”这个技术概念。客户端可以像“最近任务”一样自动处理：

- 打开 `initiated_by_me` 且仍为 `open` 的会话时，自动加载必要上下文。
- 上下文只绑定到该历史会话 tab，不污染默认本地数字员工上下文。
- 关闭 tab 后释放临时上下文；再次打开时按需恢复。
