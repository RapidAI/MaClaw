# iWorker —— 企业 AI Native 组织运行系统

---

## 您的企业，准备好进入 AI Native 时代了吗？

过去两年，几乎所有企业都在尝试 AI。

有的把 AI 当搜索框，有的当写作助手，有的当客服插件，有的当自动化脚本引擎。

这些工具确实能提升局部效率，但一个根本问题始终没有被解决——

**企业能力长期沉淀在个人经验、部门黑箱和碎片化系统里。**

- 关键岗位一旦变动，业务能力跟着流失
- 组织协作依赖熟人经验，难以标准化复制
- 老板看得到结果，看不到过程，也推不动持续改进
- AI 只能做零散动作，不能成为真正的组织成员

**企业需要的不是更多 AI 插件，而是一套新的组织操作系统。**

---

## iWorker 是什么？

iWorker 不是一个 AI 助手，也不是一个聊天入口。

**iWorker 是一套帮助企业构建 AI Native 组织的数字员工系统。**

它让企业把工作交给数字员工，把能力沉淀到系统，把经营从"依赖人"升级为"依赖组织化的 AI 系统"。

### AI Native 组织，不是"员工在用 AI"，而是"组织本身以 AI 为原生能力来运行"

在这样的组织里：

| 传统组织 | AI Native 组织 |
|---------|---------------|
| 工作零散分配给个人 | 工作分配给角色化、能力化的执行单元 |
| 流程写在制度里 | 流程运行在系统里 |
| 知识沉淀在少数人脑中 | 知识沉淀在组织中枢中 |
| 管理事后看报表 | 实时感知、解释、决策与推动执行 |

## 一、iWorker：数字员工前台

iWorker 是数字员工直接承接任务、调用技能、协同执行的工作前台。

**它不是聊天窗口，而是数字员工的工作界面。**

一个任务进入系统后，iWorker 负责：

- **接收目标与上下文** —— 理解任务意图，识别所需角色与技能
- **调用工具、知识与流程** —— 打通本地文件、浏览器、桌面、IM、语音和外部系统
- **多 Agent 协同执行** —— 交互 Agent 对话、执行 Agent 调工具、监控 Agent 保进展
- **与人类员工协作** —— 人类作为高价值判断节点参与关键决策
- **交付结果并沉淀过程** —— 执行反馈上报 iWorkerCenter，进入组织记忆

### 多 Agent 运行时

每个 iWorker 可同时运行多个 Agent 实例：

| Agent 类型 | 职责 |
|-----------|------|
| **交互 Agent** | 承接 IM / 语音对话，理解意图，分派任务 |
| **执行 Agent** | 调用工具、执行流程、生成交付物 |
| **监控 Agent (Watcher)** | 后台 GoalWatch，响应 Center push，自动恢复停滞任务 |

### iWorker 不负责

- 成为企业记忆真源（权威在 iWorkerCenter）
- 成为组织任务状态真源
- 成为 skill、workflow、审计的权威存储点

> **iWorker 是身体的本地执行层，记忆和能力的权威沉淀始终在 Center。**

## 二、iWorkerCenter：AI Native 组织中枢

iWorkerCenter 是整个系统的组织大脑。它不只是后台配置中心，而是企业能力真正沉淀的地方。

### 四层架构模型

```
┌─────────────────────────────────────────┐
│        Executive Layer · 经营层          │
│   经营诊断 · 资源配置 · 风险预警          │
│   决策模拟 · 推动执行                    │
│   (面向 CEO / 董事会)                   │
├─────────────────────────────────────────┤
│        Management Layer · 管理层        │
│   任务 SLA · 质量评分 · 运营指标         │
│   资源利用率 · 风险监控 · 组织健康       │
├─────────────────────────────────────────┤
│      Organization Layer · 组织层        │
│   岗位与角色 · 技能地图 · 跨部门协作     │
│   授权边界 · 任务路由 · 升级机制         │
├─────────────────────────────────────────┤
│       Execution Layer · 执行层          │
│   iWorker 数字员工 · 自动化执行单元      │
│   接收任务 → 调用工具 → 执行流程 → 交付  │
└─────────────────────────────────────────┘
```

### 核心能力

#### 1. 组织记忆系统

三级记忆体系，让企业能力从"个人所有"变为"组织所有"：

- **公司级记忆** —— 战略、制度、行业知识、通用规则、历史案例
- **部门/能力域记忆** —— 虚拟组织单元的经验、流程、规范和业务知识
- **个人级记忆** —— iWorker 或真人员工的偏好、上下文、任务状态和个性化经验

#### 2. GoalWatch 执行守护

AI Native 组织不能假设一次 LLM 调用会持续推进到任务完成。

GoalWatch 是组织执行心跳：

- **任务级** —— 发现未接受、未开始、执行中长时间无反馈
- **Workflow 级** —— 发现流程步骤超时、前后步骤断裂、责任人不可用
- **A2A 级** —— 发现协商会话长期 open、方案无 review、决策未形成
- **目标级** —— 发现经营目标偏离、关键指标恶化、行动项未闭环
- **能力域级** —— 发现某个虚拟组织单元持续积压、质量下降或经验未沉淀

**它不替老板做重大决策，也不替 iWorker 执行业务，但它能防止目标因 LLM 中断、工具失败、Agent 离线或协作停滞而悄悄死亡。**

#### 3. Executive Skills —— 经营层能力

让 iWorkerCenter 从"汇报工具"升级为"经营操作系统"：

| 类别 | 解决什么问题 | 典型问题 |
|-----|------------|---------|
| **经营诊断** | 发生了什么，为什么 | 本月营收为什么低于目标？毛利下降是价格问题还是结构问题？ |
| **资源配置** | 资源该投到哪里 | 哪条业务线值得加大投入？哪些动作 ROI 最低应停止？ |
| **风险预警** | 不管会演变成什么风险 | 哪些客户存在高流失概率？哪些项目有延期风险？ |
| **决策模拟** | 如果做某动作会怎样 | 压缩 10% 预算应先压哪里？增加销售投放交付侧是否接得住？ |
| **推动执行** | 决策如何真正落地 | 这项经营动作由谁推进？需要调动哪些数字员工？如何跟踪？ |

每个 Executive Skill 完成七步闭环：**数据接入 → 现状描述 → 原因分析 → 决策选项 → 建议动作 → 执行编排 → 跟踪指标**

#### 4. 企业内部 Skill Market

能力自运营、自评价、自进化的生态：

- **Cloud 导入** —— 从 iWorkerCloud 搜索、购买或获取免费 Skill
- **自总结 Skill** —— iWorker 在执行中自动沉淀可复用经验为企业自有能力
- **本地创建** —— 管理员或员工手工创建维护

**成熟 Skill 可按规则上传到 iWorkerCloud，通过管理员邮箱关联收益——让企业能力变为可商业化的资产。**

#### 5. 虚拟组织架构

传统公司依靠中层拆解战略、分派任务、汇报进度、升级异常。

在 iWorker 体系里，这些功能主要由系统完成。中层和部门不再是一层固定人墙，而是系统中的：

- **能力域** —— 定义一类业务能力
- **记忆域** —— 沉淀相关经验、规则和案例
- **权限域** —— 决定谁能访问什么
- **路由域** —— 按能力分配任务，而非汇报线
- **指标域** —— 展示能力域状态、瓶颈和改进空间

> **中层管理不再是一批人，而是一组可审计、可演进、可替换的系统能力。**

## 三、iWorkerCloud：厂商云端管控平台

iWorkerCloud 是我们作为系统厂商提供的云端平台。

**它只做三件事，绝不越界：**

| 负责 ✅ | 不参与 ❌ |
|--------|----------|
| iWorkerCenter 授权与多租户管理 | 不调度客户公司的任务 |
| 算力分发与计费 | 不读取客户企业记忆 |
| 顶级 Skill Market & 商业结算 | 不替代客户自己的 iWorkerCenter |

**企业数据、组织记忆、经营判断——全部留在客户自己的 iWorkerCenter 中。**

## 四、安全与高可用

### 数据主权

- 所有企业数据保存在客户自有的 iWorkerCenter
- iWorker 本地只做缓存，不持有权威数据
- iWorkerCloud 只处理授权和算力，不碰企业经营数据

### 高可用架构

- iWorkerCenter 支持多节点部署、主备或多机热备
- GoalWatch 支持 Watcher Shard 分片，多机并发检查
- 配置与状态同步，故障切换后持续提供组织中枢能力
- 记忆、流程、任务和经营视图在高可用模式下保持一致

### 审计追踪

- GoalWatch push 与 ack 全部写入协作事件表
- 任务全生命周期可审计
- Skill 演化、发布、跳过原因结构化记录
- 经营动作下发、执行、回收全程可追溯

## 五、客户价值总结

### 您的企业将获得三件事

**第一，获得一支可上岗、可协作、可进化的数字员工队伍。**

数字员工承接任务、调用技能、与人类员工协作，交付结果并沉淀过程。它们不会离职，不会遗忘，能力持续增长。

**第二，获得一个不依赖关键人的组织中枢。**

知识、流程、协作方式与经营判断被持续沉淀进系统。企业能力从"个人所有"转变为"组织所有"，不再因人员变动而丢失。

**第三，获得一个面向管理层和老板的经营操作系统。**

老板不仅能看数据，更能让系统解释数据、形成选项、调用资源并推动执行。从被动看报表，变为主动经营。

## 六、为什么是现在？

今天的企业环境有一个明显趋势：

- 人才流动更快
- 业务变化更快
- 管理半径更大
- 竞争反应时间更短

在这种环境下，过度依赖个人、过度依赖线下默契、过度依赖静态流程，会让企业越来越脆弱。

**未来真正有韧性的公司，不是人最多的公司，而是组织能力沉淀最深、可复制性最强、经营响应最快的公司。**

iWorker 的意义，就在于帮助企业先一步进入 AI Native 组织形态。
