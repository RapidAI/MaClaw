# iWorker 交互架构与终端定位

## 一句话原则

本地工作电脑不是数字员工系统的中心，只是 `iWorker` 的身体与执行容器；真正的组织中枢在 `iWorkerCenter`，真正自然的协作入口在 IM 与语音。

## 一、终端重新定义

在传统软件时代，员工主要通过本地电脑打开各种系统完成工作。

但在 `iWorker` 体系里，这个关系应该反过来：

- 不是人围着软件工作
- 而是数字员工围绕任务持续工作
- 人类只在必要节点介入判断、授权、协同或例外处理

因此，本地工作电脑的角色不再是“工作中心”，而是边缘执行节点。

## 二、本地电脑是什么

### 1. iWorker 的身体

`iWorker` 需要一个可以接入文件、浏览器、桌面环境、企业 IM、语音输入输出、外部系统的本地执行体。

所以本地电脑首先是数字员工的身体。

它负责：

- 调用本地工具
- 访问本地文件
- 操作浏览器与桌面界面
- 与 IM、语音、摄像头、麦克风等终端能力连接
- 提供低延迟的本地响应与缓存

从这个角度看，电脑更像数字员工在现实世界中的行动容器。

### 2. 人类员工的工具容器

人类依然会使用电脑，但用途会明显收缩。

未来更常见的情况不是人全天盯着电脑操作，而是：

- 通过 IM 接收数字员工汇报
- 通过语音给数字员工下达任务
- 在关键节点打开电脑做判断或审批
- 在少数专业场景中调用复杂工具

也就是说，电脑对人类越来越像一个按需打开的工具箱，而不是持续占据注意力的主工作场所。

### 3. 边缘节点而不是能力中心

本地电脑可以缓存、加速、临时离线运行，但不应成为组织能力的真正沉淀点。

真正的知识、记忆、流程与组织状态，必须沉淀在 `iWorkerCenter` 中。

## 三、真正的交互入口应该是什么

如果 `iWorker` 是数字员工体系，那么人类和数字员工的自然交互入口，不该主要是复杂 GUI，而应是：

- 企业 IM
- 语音
- 任务流
- 汇报流
- 异常提醒与追问

### 1. IM 是默认工作入口

IM 是最贴近组织协作习惯的入口。

员工和老板更自然的方式是：

- 直接找某个数字员工伙伴
- 在群里发起任务
- 接收阶段汇报
- 追问原因
- 下发下一步动作

这比要求每个人进入复杂后台页面更符合真实工作流。

### 2. 语音是更自然的人机协作方式

很多管理动作和协作动作，本质上并不需要打字。

例如：

- “帮我看下今天有哪些异常需要我处理”
- “把这个客户情况整理给销售和交付两个数字员工”
- “把这个月营收偏差的原因给我讲清楚”
- “通知运营团队按这个方案推进”

这些命令天然适合通过语音完成。

所以，数字员工体系的未来主交互应是“IM + 语音”，而不是“鼠标点击 + 表单填写”。

### 3. GUI 是补充控制台，不是唯一入口

GUI 依然重要，但它的定位要被重新定义。

它主要用于：

- 查看全局状态
- 配置组织规则
- 查看复杂图表与结构信息
- 做权限、流程、角色等管理动作
- 调试、审计、追踪历史过程

因此 GUI 更像控制台，而不是每个任务的主要发起入口。

## 四、人类与数字员工如何协作

在这套架构下，人类员工与数字员工的协作方式应当是：

- 日常任务通过 IM 和语音分派
- 数字员工持续执行、汇报与跟进
- 人类在高价值节点给出判断和授权
- 复杂材料与专业软件在本地电脑上被按需调用
- 所有过程和能力沉淀回 `iWorkerCenter`

这意味着人类不再是唯一执行主体，而更像：

- 判断节点
- 授权节点
- 责任节点
- 关系节点
- 极端例外的接管者

## 五、为什么能力不能沉淀在本地电脑里

如果记忆、知识、流程、经验主要沉淀在本地设备上，会带来严重问题：

- 换人就丢能力
- 换电脑就丢上下文
- 多端协同无法统一
- 管理层看不到真正组织状态
- 企业仍然依赖个人和设备，而不是依赖组织系统

所以从架构原则上必须明确：

- 本地电脑可以缓存
- 本地电脑可以加速
- 本地电脑可以临时存草稿
- 但本地电脑不是组织能力的真源

真正的真源应在 `iWorkerCenter`。

## 六、产品分层定位

### iWorker

定位为数字员工前台与本地执行体。

重点能力：

- IM 接入
- 语音交互
- 本地工具调用
- 桌面与浏览器执行
- 文件接入
- 本地缓存与短时离线

### iWorkerCenter

定位为 AI Native 组织中枢。

重点能力：

- 组织记忆
- 角色能力
- 工作流与协作
- 管理与经营视图
- Executive Skills
- 审计与策略沉淀

### iWorkerCloud

定位为云侧平台与跨中心基础设施。

重点能力：

- 多中心接入
- 授权与 license
- 云算力
- 跨中心同步
- 远程管理与平台运营

## 七、对 GUI 设计的直接影响

既然本地电脑不是中心，`iWorker` GUI 就不应该设计成传统重后台。

更合适的方向是：

- 更像数字员工驻留终端
- 更强调在线伙伴感
- 更强调任务流与汇报流
- 更强调语音和 IM 联动
- 更少堆积复杂设置项
- 更像“执行面板”而不是“系统后台”

而 `iWorkerCenter` GUI 则应更像：

- 组织驾驶舱
- 管理控制台
- 经营视图
- 能力沉淀中心

## 八、最终结论

未来的工作终端不再是“人打开电脑操作软件”，而是：

- 人通过 IM 与语音和数字员工协作
- 数字员工在本地电脑这个身体里执行动作
- 企业能力沉淀在 `iWorkerCenter`
- 云侧能力由 `iWorkerCloud` 提供支撑

所以，电脑不再是工作的中心，只是数字员工的身体、人类偶尔调用的工具，以及组织系统在边缘侧的执行容器。
