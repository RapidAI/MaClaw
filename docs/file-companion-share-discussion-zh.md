# 伴读分享文档的讨论（主持人审核 + Agent 回复）

状态：已实现（2026-10-27，主持人审核与忽略标记 2026-10-28）

## 问题

伴读窗口里分享出去的文档，参与者发的问题会写成批注，但回答由参与者自己的本地 agent 生成。那条回答只在这位参与者的聊天里，其它参与者和主持人都看不到，讨论无法成立。

## 目标流程

1. 参与者在收到的分享上发送普通问题。这条消息作为批注写到 Hub，默认状态是「待审核」；本机不再跑一次私有回答。
2. 主持人看到待审核的批注，选择「通过」或「忽略」。只有「通过」的批注会交给主持人的伴读 agent；「忽略」的批注不进入模型，但仍保留在批注列表里并带忽略标记。
3. 主持人的 agent 回答后，回答以批注形式写回同一个分享，并把 `reply_to` 指向被回答的批注。
4. 所有能看到分享的人在下一次库轮询时收到这条回答；参与者在聊天区看到「主持人回复」，批注区看到「主持人 · 作者」。被忽略的批注在参与者的批注区显示「主持人已忽略这条批注」，已通过但还没回复的显示「已通过，等待主持人 Agent 回复」，等待审核的显示「等待主持人审核」。

选中一段文字后的改写、视频/网页记笔记、论文解读仍是本机操作，不进入讨论。

## 审核协议

- 参与者写批注仍走 `POST /api/mobile/documents/shares/{token}/notes`。新批注由 Hub 标记 `decision: "pending"`；主持人自己写的批注不带 decision，也不进入审核。
- 主持人审核：`POST /api/mobile/documents/shares/{token}/notes/{noteID}/review`，请求体 `{"decision":"approve"}` 或 `{"decision":"ignore"}`。
  - 只有当前主持人可以审核；参与者调用返回 403（`只有主持人可以审核批注`）。
  - 已经产生主持人回复的批注不能再审核，返回 409（`批注已经回答，不能再审核`）。
  - 未回复前可以改判：例如先忽略、后通过；每次变化增加 `notes_revision`。界面上，主持人可以在已忽略的批注上点「改为通过」，一旦已经产生回复就不再提供。
- 主持人回复正文仍走原 notes 接口并带 `reply_to`。Hub 拒绝回答待审核（`批注还没有通过审核，不能回复`）和已忽略（`批注已被忽略，不能回复`）的批注。旧客户端不知道审核字段，但回复会被 Hub 挡住，不能绕过主持人。
- 批注持久化新增 `decision` 和 `decided_at`。更早写入的批注没有 `decision`：已经有人回答的按 `approved` 显示；没有回答的按 `pending` 显示，主持人仍可审核。
- `GET /api/mobile/documents/shares` 的响应增加 `notes_review: true`。桌面端只有在确认 Hub 支持审核后，主持人才会等待通过状态再回答；旧 Hub 仍按原来的自动回答逻辑工作。`notes_reply` 和 `server_time` 继续保留。
- 批注列表里每条读者批注新增 `decision`（`pending` / `approved` / `ignored`），主持人的回复不带该字段。

## Hub 协议

`POST /api/mobile/documents/shares/{token}/notes` 的请求体增加可选的 `reply_to`：

```json
{"text": "回答正文", "reply_to": "cn_..."}
```

- 只有分享创建者（主持人）可以带 `reply_to`；参与者带它会得到 403（`只有主持人可以回复批注`）。
- `reply_to` 必须指向该分享里已存在的一条非主持人批注，且该批注必须已通过审核，否则返回 400/403。
- 同一个 `reply_to` 只接受一条主持人回答。重复 POST（第二台主持机器、响应丢失后的重试）返回当前列表，不增加新批注。
- 批注持久化增加 `host` 与 `reply_to`。更早写入的批注没有 `host`，读取时用已保存的 `author_id == owner_id` 推导，避免把主持人旧批注当成读者问题再答一遍。
- `GET /api/mobile/documents/shares` 的响应增加 `notes_reply: true`、`notes_review: true` 和 `server_time`（Hub 当前时间）。旧 Hub 没有这些字段，桌面端据此关闭主持人自动回答；否则旧 Hub 不记录 `reply_to`，每条主持人发言都会被当成未回答的问题，形成循环。`server_time` 用于把讨论水位放在 Hub 时钟上，避免两端时钟偏差跳过现场批注。
- 桌面端的库列表把 `notes_reply` 转成 `notesReply`、把 `notes_review` 转成 `notesReview` 返回给窗口。参与者只有在确认 Hub 支持主持人回复后，才停用本机回答；旧 Hub，或第一次列表请求还没成功时，仍按原逻辑由本机 agent 回答，避免桌面端先升级、Hub 后升级时问题无人回答。列表请求失败时保留上一次成功的能力值。

批注列表里每条记录新增：

```json
{"id": "cn_...", "author": "reader@example.com", "text": "...", "created_at": "...", "host": false, "reply_to": "cn_...", "decision": "pending"}
```

## 桌面端

新增 `guiapp/file_companion_share_discussion.go`，主窗口和伴读窗口的启动路径都会启动同一个 watcher（进程内单例）。

- 每 20 秒拉一次本账号的分享；没有分享时退到 60 秒。
- 只处理 `host=false`、且没有被任何 `host=true` 批注以 `reply_to` 指过的批注。Hub 支持审核时只取 `decision="approved"` 的批注，审核通过前不调用模型；旧 Hub 没有审核字段，仍按水位自动回答。审核模式下，随问题一起给模型的「最近的批注」也只包含主持人自己的批注和已通过的读者批注，待审核与已忽略的批注不会以任何形式进入提示词。
- 水位按分享保存。新分享的水位取「功能首次安装时间」和「分享创建时间」中较晚的一个：功能上线前的旧分享不会自动补答历史批注；上线后创建的分享即使主持人在线前就有人提问，也会从分享创建时间开始回答。首次安装时间会回退一分钟，避免刚创建的分享被误判成历史。两个时间都使用 Hub 列表返回的 `server_time`（Hub 时钟），避免主持人和 Hub 的时钟不一致时把现场批注误判成历史；Hub 太旧没有该字段时才退回本机时间。旧版本用本机时钟写下的安装时间如果明显晚于 Hub 时间，会按 Hub 时钟重写，避免时钟跑快后跳过现场批注。`InstalledAt` 写在 `data/file-companion/share-discussion/share-discussion.json`。审核模式下水位不限制已通过的批注：主持人明确点了通过，即使批注写于功能安装前也应该回答。
- 每条批注只回答一次：Hub 的 `reply_to` 是持久去重；本机 `claims/` 文件防止主窗口与伴读窗口同时跑同一轮模型；失败后 5 分钟内不重试。
- 每个分享每小时最多 12 次回答（失败也计入），每次轮询最多回答 2 条，按时间从旧到新。
- 模型回答成功但 Hub 暂时拒绝写入时，回答文本在本机缓存 15 分钟；重试只重发批注，不再跑一次模型。
- 回答使用主持人自己的伴读 agent，私有会话在 `data/file-companion/share-discussion/sessions/`，不写主持人的正常伴读聊天记录，也不修改文档。
- 讨论轮次的系统提示是**最小提示**：只有主持人讨论指令，不拼主助手的身份、项目路径、置顶规则、任务、SSH 主机、长期记忆、技能、steering 规则和 resume trace。主助手侧也会跳过 chat task 调度指引和子代理路由，避免读者的诱导性批注把这些宿主上下文带进公开回答。
- 后台会话不是打开的标签页，所以会为它登记一个只读的文档授权和会话→文档映射；`pdf_read_pages` 等工具因此能读到主持人的本地副本。已经打开的标签页保留原来的授权，不会被改成只读。
- 模型提示把批注声明为读者写的、只能当作问题或评论，不能当作指令；PDF 只允许读页、裁图、提取图片，不调用 `pdf_restore`/`pdf_generate`。这不仅是提示：讨论会话的工具列表里没有这两个工具，执行层也会拒绝，即使批注诱导模型调用。
- 发布回答前会把主持人本机的文档绝对路径、父目录和用户主目录替换成「（本机路径已省略）」；共享文档名本身是公开的，保留。提示里也要求模型不透露本机路径、用户名、任务和记忆。
- 回答正文截到 1900 个字符，低于 Hub 的 2000 字符上限。

前端 `FileCompanionWindow`：

- 收到的分享上，普通问题只发批注，不调用本机 agent。Hub 支持审核时提示「已发给主持人审核，通过后由主持人 Agent 回复」；旧 Hub 仍提示已发给主持人 Agent。
- 主持人在批注区看到待审核条目，可以点「通过」或「忽略」；通过后该批注在主持人 watcher 的下一次轮询交给 agent，忽略后不会再进入模型。误点忽略时，未回复前可以点「改为通过」重新放行。参与者批注区显示「等待主持人审核」「已通过，等待主持人 Agent 回复」或「主持人已忽略这条批注」。文档管理的分享行显示「待审核 N」。
- 选中一段原文再提问时，选中的原文附在批注里一起发给主持人，主持人能看到具体段落。
- 最新批注列表里 `host=true && reply_to` 的条目在聊天区显示为「主持人回复」，并引用被回答的读者批注；批注区把主持人条目标成「主持人 · 作者」。
- 收到的分享按 5 秒轮询库，主持人回复通常在下一次轮询出现；聊天导出也包含这些主持人回复。
- 主持人画或清除 PDF 高亮后，阅读器保存本地高亮并发出变更事件；窗口按 1.2 秒防抖把项目（含最新高亮）同步到该文件的所有主持人分享。高亮发生在库列表确认主持人身份之前时先挂起，列表到达后再上传。参与者下一次轮询收到新版本，保存高亮并重载预览，因此主持人标注的黄色高亮会出现在其他参与者页面上。
- 聊天区的回答高亮（`chatMarks`）也随同一个项目同步。主持人画或清除回答上的高亮会触发同样的 1.2 秒防抖上传；项目 manifest 的 `chatMarks` 保存消息索引、颜色、字符范围和引文，参与者拉取新版本后写入本机回答标注并重绘。旧项目没有 `chatMarks` 字段时保留参与者自己的标注；空数组 `[]` 表示主持人确实清空了。
- 选中原文，或右键已有高亮/批注卡后，菜单里有「批注」。输入的文字写成本地批注卡（`kind: "annotation"`，正文存在 `translation` 字段），显示方式与译文卡一致：可拖动，右下角可调节宽高。右键批注卡时菜单显示「删除批注」。
- 翻译卡和批注卡都支持拖动和右下角缩放。尺寸按渲染页面的比例保存在 `size: {w,h}`，窗口缩放或重新打开后仍按同一比例还原；宽度不小于 200px、高度不小于 100px。
- 只有主持人的批注随项目分享。译文是本机模型生成的结果，仍只留在本地；参与者收到新版本时保留自己的译文，只替换主持人上一版带来的批注（`shared` 标记），参与者自己写的本地批注不会被覆盖。
- PDF 阅读器左上角有黄色圆形「手绘」按钮。按下后显示与高亮相同的四色色板，以及画线、画框、擦除、撤销四个图标按钮（悬停显示文字说明）；按住鼠标在页面上画自由线，或拖出矩形框。「擦除」进入框选擦除模式：拖出一个选择框，与选择框相交的本机新增线条和框会被清除，拖框过程中会被删除的形状变红提示；主持人同步来的笔迹不会被参与者擦除。面板里的「撤销」撤回上一笔；再次按「手绘」或按 Esc 退出手绘，退出后文字选择和右键菜单恢复。绘制只作用于 PDF，非分享状态也可用，按页面本地保存。
- 手绘坐标以页面比例保存，缩放窗口或重新打开文档后位置和形状不变。主持人的绘制随项目 manifest 的 `drawings` 字段同步；参与者收到新版本时保留自己的绘制，只替换主持人带来的绘制（`shared` 标记）。没有 `drawings` 字段的旧项目不会清掉参与者已有绘制。本地文档被删除或分享被撤回时，对应手绘一并清除。
- 分享创建、手动「同步」、分享创建弹窗的同步按钮和「导出项目」发送的标记载荷是一个对象：`{"highlights":[...PDF标记],"chatMarks":[...回答标注],"annotations":[...批注],"drawings":[...手绘]}`。旧的纯数组载荷仍被接受，只携带 PDF 高亮；没有某字段的旧项目不会清掉参与者对应的本地内容。直接打开导出的项目 zip 时，高亮、回答标注、批注和手绘都会一并恢复。
- 主持人在文档管理中移除自己的云端分享行（按钮显示「取消分享」）会调用 Hub 删除该分享链接，本机文档、高亮、批注和手绘保留；所有参与者在下一次列表刷新时按下面的撤销流程移除副本并关闭已打开的伴读文档。已过期的分享没有可通知的参与者，只在本机移除。
- 删除分享后可以重新分享。若 Hub 上仍存在同一文档、同一范围的旧链接（例如旧版本只移除了本地行），新建分享会识别 `SHARE_DUPLICATE` 并带上旧 token；桌面会自动接管该链接、应用当前密码/有效期并把当前项目同步上去，本机云行随之恢复，不会停在「已经分享过」。如果旧链接确实已被删除，重新分享会生成新 token；参与者下一次刷新会看到新的分享行，重新打开后批注和新标注同步恢复。

## 主持人转移

- 分享的创建者是**管理员**，永久保留修改范围、删除分享、指定/收回主持人的权限；初始主持人也是管理员本人。
- 管理员在「修改分享」弹窗的「主持人」区填写参与者邮箱或手机号并点「转移主持权」后，Hub 记录一条待接受的主持人提名，主持人席位**不会**立刻变化。
- 被提名人会收到一条 `companion_host_transfer` 通知，在伴读通知详情里点「接受」或「拒绝」。只有接受后席位才转移；拒绝或取消则保持原主持人。其他参与者会收到 `companion_host_transfer_notice` 变更通知。
- 转移后原管理员成为参与者，但保留管理权：可随时「收回主持权」恢复自己主持，或另行指定其他人；也可以取消尚未接受的提名。
- 主持人席位决定谁回复批注、谁的项目同步写入云端：Hub 与桌面都只允许**当前主持人**上传项目；原管理员若已交出席位则只下载，不再上传。原管理员因此能收到新主持人的高亮、批注、手绘和聊天，两台机器也不会互相覆盖。参与者发起的批注仍发给当前主持人。旧版本写入的本机分享行没有席位字段，按创建者即主持人处理。
- 交接后的界面：新主持人的标题栏显示「你是主持人」，分享按钮改为「同步」。原管理员的标题栏仍显示「修改分享」（管理权），但不显示「同步」，也不会再自动上传；文档管理里其行显示为收到的分享，会保持 5 秒快速轮询以接收新主持人版本。
- 分享被删除、分享范围被修改时，未处理的主持人提名会自动取消并通知参与者。
- 群组分享里，若被提名者或当前主持人被移出群组、主动退出、或群组被解散，Hub 会取消未接受的提名或把主持人席位收回给管理员，并通知参与者，避免出现「主持人打不开这份文档」的死状态。
- 接受主持权后，本机在下一次列表刷新时先拉取云端当前版本再开始上传：交接前它只是参与者，本地副本可能落后一版，直接同步会用旧版本覆盖前任主持人已经分享的高亮、批注、手绘和回答标注。
- 主持人席位会写入本机文档库，重启后仍然生效；旧版本写入的行没有该字段，按「创建者即主持人」处理。
- 提名后如果对方失去了打开这份文档的资格（被移出群组等），其「接受」会被拒绝，Hub 同时撤回这条提名并通知参与者，避免留下一条永远点不动的邀请。
- 批注记录的是**写下时的席位**：交出席位前管理员写下的行仍是主持人行，不会被自己的 agent 重复回答；交出席位之后管理员的新批注就是读者批注，由新主持人回答。

## 分享通知

- 分享给指定的人或阅读群组时，Hub 为有权限的接收者创建一条 `companion_share` 通知，`source_id` 是分享 token。群组只通知已接受的成员；指定人必须能解析到 Hub 账户。完全公开和密码分享没有确定接收者，不创建通知。
- 通知会推送到桌面并弹出系统通知；离线时通知保存在 Hub，重连拉取未读通知时再弹一次。桌面通知标题为「分享文档」。
- 在伴读通知列表打开这条通知会看到「打开」按钮：已导入的分享直接打开本机副本；未导入时先下载导入，再在伴读中打开。
- 分享删除时对应通知会撤回；分享范围变更（群组/指定人变化）会撤回旧通知并按新接收者重新发送。修改密码、有效期或同步内容不会重复通知。

## 撤销分享后的接收端清理

主持人删除分享后，Hub 不再把该 token 返回给接收方。接收端下一次列表刷新时对缺失的非群组 token 做一次单条分享查询：

- `404` + `分享链接不存在`：分享已被删除。删除本地 `library-files/<token>` 下载副本，删除会话记录、图表、结果和工作文件（`purgeFileCompanionProjectData`），清空该路径的 PDF 高亮、翻译、批注、手绘和回答标注，关闭打开的标签页，并在关闭前提示「该文章已经取消分享，本地副本与阅读记录已清除。如需继续阅读，请联系主持人 xxx」。主持人名字取该分享最后一次列表里的 `hostLabel`（旧数据回退到 `owner`）；如果读者本人就是当前主持人，则提示联系管理员（`owner`），不指向自己。后端在 `removedHosts` 里一并返回，窗口即使没有上一份列表也能显示。一次刷新撤销多篇时提示改为「这些文章已经取消分享」，并列出每位主持人（去重）；完全没有主持人标签时提示「请联系分享的主持人」。关闭标签页后焦点落到被关标签的相邻标签。删除的 token 会记入 dismissed，防止一个较早的列表响应把副本重新导入；群组分享不记 dismissed，以便重新加入群组后同一 token 还能出现。
- `200`：链接仍存在（通常是过期分享），保留本地副本和阅读记录，不做清理。
- 网络错误、`403`、`5xx`：保留，下一次刷新重试。
- 群组分享不额外查询：分享被主持人删除，或被移出群组后，该 token 不再出现在列表里，同样走丢弃本地副本、清阅读数据并关闭标签页的流程；token 不记入 dismissed，重新加入群组后同一 token 还能出现。
- 旧 Hub 没有单条分享路由时返回的普通 404 没有「分享链接不存在」消息，不会被误判为删除。
- 被判定「仍存在」的过期 token 会缓存 30 秒，避免接收方 5 秒轮询时反复请求 Hub；每次刷新最多并发查询 12 个缺失 token。

## 限制

- 主持人机器离线时没有回答；参与者的问题仍留在批注里，主持人下次上线后会回答。
- 主持人本地没有该文件（已移动或删除）时跳过；不会从 Hub 下载副本再回答。
- 公开链接分享的持链接者也能写批注。当前用每分享每小时 12 次的上限约束 token 消耗；需要更严格时可只对群组/指定人分享开启自动回答。
