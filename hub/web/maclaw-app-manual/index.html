快速上手

MaClaw 应用工作室使用手册

把 Skill、工作流、MIS/DataSrv 能力变成一个用户能点击运行的业务应用。按“选类型 → 绑定能力 → 运行验证 → 发布或自用”走，就能快速完成。

1. 3 分钟上手

1进入工作室

左侧导航「应用」→「工作室」。

2选择类型

不确定就先选「工具应用」。

3绑定能力

选择 Skill，或填写业务对象 / DataSrv 信息。

4运行一次

确认输入、结果、产物和审批状态正常。

5发布或自用

提交企业市场，或仅添加到本机面板。

2. 界面地图

创建应用

从能力生成应用入口，填写名称、说明、图标、输入输出和布局。

应用管理

固定、排序、复制、编辑、停用、恢复应用，并查看 Manifest。

审核 / 发布

按检查清单补齐证据、依赖和治理信息，再提交企业市场。

3. 选择应用类型

工具应用我已有本地 Skill，要做成一个按钮入口。文档处理、生成报告、文件转换、信息查询。
自动化应用我要按固定规则重复运行。定时检查、批处理、监控后触发。
企业普通应用我要连接企业数据或业务对象。客户、订单、库存、合同等 MIS/DataSrv 场景。
企业审批应用我要让流程进入审批和复核。报销、合同、变更、工单、敏感操作确认。

4. 创建应用：最短填写法

选类型写一句说明绑定 Skill配置结果保存
  1. 名称写成用户能理解的动作，例如「合同归档」「客户活跃度报告」。
  2. 说明只写一句话：这个应用会处理什么输入，输出什么结果。
  3. 绑定 Skill 或业务对象；企业应用再补 DataSrv/MIS 字段。
  4. 结果契约里至少保留用户可复核的信息：摘要、文件、状态或记录 ID。
  5. 保存到 Skill 定义用于复用；临时自用可选择仅添加到面板。
最小可用标准：用户知道它做什么，能运行一次，并能看到可复核的结果。

5. 发布前运行验证

  • 输入字段命名清楚，不需要额外解释。
  • 运行结果能复核，有摘要、记录或产物。
  • 产物文件可以打开、下载或定位。
  • 审批应用能产生审批状态和处理记录。
  • 依赖 Skill 已安装，版本没有明显冲突。
  • DataSrv/MIS 连接、租户和权限已配置。

6. 完成标准

用户看得懂

名称和说明不依赖内部术语，用户知道该在什么场景点击它。

结果可复核

输出里有摘要、记录 ID、文件路径或审批状态，方便追溯。

发布可审核

运行证据、依赖、测试协议和治理信息没有阻塞项。

7. 审核 / 发布

打开审核/发布看检查清单修缺项提交企业市场等待审核

发布页会提示缺少运行证据、测试协议、工作流契约、依赖声明或治理信息。逐项修复后再提交。

Hub 暂不可用时，提交会先进入本机待同步队列。恢复连接后再同步到企业能力市场。

8. 常见问题

常见误区：只创建入口但没有运行证据；说明写成内部代号；结果只有“成功”但没有可复核内容；依赖 Skill 没有安装就提交。

不知道选哪种类型

先选「工具应用」。确认需要企业数据、审批或固定自动化后，再换对应类型。

发布按钮不可用

通常是缺少运行证据、测试协议、依赖声明或企业市场连接。先看「审核/发布」里的检查清单。

依赖检查失败

安装缺失 Skill；如果依赖来自企业市场，请联系管理员确认是否允许安装。

DataSrv 未就绪

进入 MIS/DataSrv 设置，检查连接、租户、权限和业务对象配置。

1Open Studio

Apps → Studio.

2Choose type

If unsure, start with Tool app.

3Bind capability

Select a Skill or fill business object fields.

4Run once

Check inputs, results, artifacts, and approval state.

5Publish or use

Submit to market or keep it on the local panel.

2. Interface Map

Create app

Create an app entry, set name, description, icon, inputs, outputs, and layout.

Manage apps

Review / publish

Complete evidence, dependencies, and governance checks before submission.

3. Choose App Type

Tool appYou already have a local Skill and need a button entry.Documents, reports, file conversion, lookup.
Automation appYou need a fixed process to run repeatedly.Scheduled checks, batch jobs, monitor-triggered work.
Enterprise normal appYou need enterprise data or business objects.Customers, orders, inventory, contracts.
Enterprise approval appYou need review or approval before completion.Expenses, contracts, changes, tickets, sensitive actions.

4. Create App: Shortest Fill Path

Choose typeOne-line descriptionBind SkillConfigure resultSave
  1. Name it as a user action, such as Contract Filing or Customer Activity Report.
  2. Use one sentence: what input it handles and what result it returns.
  3. Bind the Skill or business object. For enterprise apps, fill DataSrv/MIS fields.
  4. Keep reviewable output: summary, file, status, or record ID.
  5. Save to Skill definition for reuse, or add to panel only for temporary local use.
Minimum usable app: users know what it does, can run it once, and can review the result.

5. Run Check Before Publishing

  • Input field names are clear.
  • Results include a reviewable summary, record, or artifact.
  • Artifacts can be opened, downloaded, or located.
  • Approval apps create approval state and records.
  • Required Skills are installed and versions look compatible.
  • DataSrv/MIS connection, tenant, and permissions are configured.

6. Done Criteria

Users understand it

Name and description avoid internal jargon, and users know when to click it.

Results are reviewable

Output includes a summary, record ID, file path, or approval state for traceability.

Publishing is reviewable

Runtime evidence, dependencies, test protocol, and governance metadata have no blockers.

7. Review / Publish

Open Review / publishRead checklistFix missing itemsSubmit to marketWait for review

The publish tab flags missing runtime evidence, test protocols, workflow contracts, dependencies, or governance metadata. Fix those items before submitting.

When Hub is unavailable, Studio keeps the submission in the local sync queue and syncs later.

8. Troubleshooting

Common mistakes: creating only an entry without runtime evidence; using internal code names as descriptions; returning only “success” without reviewable output; submitting before required Skills are installed.

Not sure which type to choose

Start with Tool app. Switch later when you need enterprise data, approval, or automation.

Publish button is disabled

Usually runtime evidence, test protocol, dependency declarations, or market connection is missing. Read the Review / publish checklist first.

Dependency check fails

Install missing Skills. For enterprise-market dependencies, ask an administrator to confirm install access.

DataSrv is not ready

Open MIS/DataSrv settings and check connection, tenant, permissions, and business objects.
