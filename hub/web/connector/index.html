MaClaw 第三方软件接入协议 v1

第三方软件主动连接 MaClaw 本机 HTTP 网关，通过简洁的 JSON 协议发送用户消息，并用长轮询获取 Agent 回复。接入方不需要提供公网回调地址。

默认地址 http://127.0.0.1:18777/api/im-gateway/v1认证 Bearer Token客户端主动长轮询

1. 接入流程

  1. 在 MaClaw 桌面端打开“设置 / 消息接入 / 第三方软件接入”。
  2. 配置 Host、Port 和 Token，默认监听本机 127.0.0.1:18777。
  3. 第三方软件调用 /handshake 获取能力和会话参数。
  4. 调用 /incoming 提交用户消息。
  5. 调用 /outgoing 使用 cursor 长轮询拉取回复，并用 /ack 确认已处理。

2. 认证

所有接口建议携带 HTTP 头：

Authorization: Bearer <token>

所有 API 调用都必须携带 Token。建议在 MaClaw 里点击“生成 Token”获取强随机密钥。如果 Token 可能泄露，请重新生成并更新第三方配置。

3. 接口

GET /health

{ "ok": true, "status": "connected" }

POST /handshake

{
  "clientId": "demo-client",
  "clientName": "Demo CRM",
  "protocolVersion": "1.0"
}

POST /incoming

{
  "eventId": "evt-20260502-0001",
  "clientId": "demo-client",
  "conversationId": "customer-42",
  "sender": { "id": "u42", "name": "张三" },
  "message": { "type": "text", "text": "帮我查一下订单状态" },
  "timestamp": "2026-05-02T10:00:00+08:00"
}

eventId 用于幂等，重复提交不会重复触发处理。

GET /outgoing

GET /outgoing?clientId=demo-client&cursor=0&timeout=25
{
  "ok": true,
  "cursor": 12,
  "messages": [{
    "id": "reply-12",
    "conversationId": "customer-42",
    "replyToEventId": "evt-20260502-0001",
    "message": { "type": "text", "text": "订单正在配送中。" }
  }]
}

POST /ack

{ "clientId": "demo-client", "messageIds": ["reply-12"] }

4. 字段约定

字段说明
clientId第三方软件实例标识，建议稳定且唯一。
conversationId第三方侧会话、客户、工单或群聊 ID。
eventId入站消息唯一 ID，用于重试幂等。
cursor出站消息游标，客户端保存上次返回值。
timeout长轮询等待秒数，建议 15 到 30 秒。

4.1 请求跟踪、错误和 ACK 语义

所有响应都会返回 requestId，第三方排查问题时建议一并提供。错误响应统一包含 ok、code、message、requestId。outgoing 使用 cursor 保证至少一次投递，第三方需要按 message.id 去重。/ack 表示第三方已将回复投递到自己的用户或业务系统，不代替 cursor 存储。

{
  "ok": false,
  "code": "bad_request",
  "message": "clientId is required",
  "requestId": "gw_1760000000000000000"
}

5. 测试客户端

$env:MACLAW_GATEWAY_TOKEN = "你的 Token"
go run ./cmd/connnectMaClaw -text "你好，确认第三方通道是否可用"

6. 错误处理

HTTP含义建议
401Token 缺失或错误检查 Authorization 头。
409重复事件或状态冲突按幂等成功处理或重新获取 cursor。
429请求过快指数退避后重试。
5xxMaClaw 处理失败保留 eventId，延迟重试。

MaClaw Third-Party Software Access Protocol v1

Third-party software connects to the local MaClaw HTTP gateway, sends user messages through a compact JSON protocol, and retrieves Agent replies through cursor-based long polling. The integrating system does not need to expose a public callback URL.

Default endpoint http://127.0.0.1:18777/api/im-gateway/v1Bearer TokenClient long polling

1. Integration Flow

  1. Open Settings / Message Access / Third-party Access in MaClaw.
  2. Configure Host, Port, and Token. The default listener is 127.0.0.1:18777.
  3. Call /handshake to negotiate protocol and capabilities.
  4. Call /incoming to submit user messages.
  5. Call /outgoing with a cursor to long-poll replies, then call /ack.

2. Authentication

Send the token with every request:

Authorization: Bearer <token>

A token is required for every API call. Use Generate Token in MaClaw to create a strong random key. If the token may have leaked, regenerate it and update the third-party configuration.

4. Field Contract

FieldDescription
clientIdStable unique ID for the third-party software instance.
conversationIdConversation, customer, ticket, or group ID from the third-party system.
eventIdUnique inbound message ID for retry idempotency.
cursorOutgoing message cursor. The client stores the last returned value.
timeoutLong polling wait seconds. Recommended range: 15 to 30.

4.1 Request Tracing, Errors, and ACK Semantics

Every response includes requestId. Third-party integrators should include it when reporting issues. Error responses consistently include ok, code, message, and requestId. /outgoing provides at-least-once delivery by cursor, so clients should deduplicate by message.id. /ack is a delivery receipt after the third-party system has delivered the reply to its user or business system; it does not replace client-side cursor persistence.

{
  "ok": false,
  "code": "bad_request",
  "message": "clientId is required",
  "requestId": "gw_1760000000000000000"
}

6. Error Handling

HTTPMeaningAction
401Missing or invalid tokenCheck the Authorization header.
409Duplicate event or state conflictTreat idempotent duplicates as success, or refresh cursor.
429Too many requestsRetry with exponential backoff.
5xxMaClaw processing failureKeep the same eventId and retry later.
