MaClaw 第三方软件接入协议 v1

第三方软件连接 MaClaw HTTP 网关，通过 JSON 发送用户消息，并使用 cursor 长轮询获取 Agent 回复。接入方不需要暴露公网回调或文件下载 URL；文件上传和下载 URL 由 MaClaw 提供。

默认地址 http://127.0.0.1:18777/api/im-gateway/v1 Bearer Token 小文件内联 大文件走服务端 URL

1. 接入流程

  1. 在 MaClaw 中打开 设置 / 消息接入 / 第三方接入。
  2. 配置 Host、Port 和 Token，默认监听 127.0.0.1:18777。
  3. 调用 POST /handshake 获取能力、限制和轮询参数。
  4. 小文件可在 POST /incoming 中直接发送 base64 data。
  5. 大文件先调用 POST /media/upload-url 获取服务端上传 URL，再由客户端用返回的 PUT URL 上传字节，随后在消息里引用返回的 media.id 或 media.url。
  6. 调用 GET /outgoing 并携带 cursor 长轮询拉取回复，然后调用 POST /ack。

2. 认证

除 /health 和带 mediaToken 保护的媒体 URL 外，请求应携带：

Authorization: Bearer <token>

请在 MaClaw 中使用“生成 Token”创建强随机密钥。如果 Token 可能泄露，请重新生成并更新第三方配置。上传和下载 URL 中的 mediaToken 由 MaClaw 生成，客户端只应使用这些 URL，不应自行构造。

3. 能力与限制

协议结构、校验器、默认限制、功能开关、严格 JSON 解码和握手响应构造集中在 corelib/im。MaClawSrv 和 MaClaw GUI 使用相同核心实现，因此 ThirdAPIDemo 客户端从任一端点看到的协议行为一致。两种服务端实现的握手 mode 均为 maclaw。

/handshake 返回的 capabilities 包含：

["text","image","file","voice","audio","attachments","server_media_upload","server_media_download","long_poll","ack","idempotency","client_tools","tool_call","tool_plan","tool_result","tool_cancel"]
限制含义
maxTextChars文本消息最大字符数。
maxMediaCaption图片、文件和语音消息说明文字最大字符数。
maxAttachments单条消息最大附件数，当前为 10。
maxDirectBytes允许直接放入 base64 data 的最大字节数，当前为 256 KiB。更大的文件必须使用服务端媒体 URL。
maxBodyBytesJSON 请求体最大大小，当前为 16 MiB。
maxMediaBytes服务端媒体最大上传大小，MaClawSrv 和 MaClaw GUI 当前均为 50 MiB。

eventId 用于幂等。重复提交同一事件不会重复触发处理。支持的 message.type 为 text、image、file 和 voice；audio 会按 voice 处理。

小文件内联

{
  "eventId": "evt-image-1",
  "clientId": "demo-client",
  "conversationId": "customer-42",
  "user": { "id": "u42", "name": "张三" },
  "message": {
    "type": "image",
    "text": "请看这张截图",
    "fileName": "screen.png",
    "mimeType": "image/png",
    "data": "<base64>",
    "sizeBytes": 12345
  }
}

对于直接传入的 data，sizeBytes 可选。若其大于零，必须等于 base64 解码后的字节数，否则网关返回 400。

大文件上传 URL

POST /media/upload-url
{
  "clientId": "demo-client",
  "type": "file",
  "fileName": "report.pdf",
  "mimeType": "application/pdf",
  "sizeBytes": 7340032
}
{
  "ok": true,
  "media": {
    "id": "server-media-id",
    "type": "file",
    "fileName": "report.pdf",
    "mimeType": "application/pdf",
    "url": "http://127.0.0.1:18777/api/im-gateway/v1/media/server-media-id?mediaToken=..."
  },
  "upload": {
    "method": "PUT",
    "url": "http://127.0.0.1:18777/api/im-gateway/v1/media/server-media-id/upload?mediaToken=...",
    "contentType": "application/pdf",
    "maxBytes": 52428800
  },
  "download": {
    "url": "http://127.0.0.1:18777/api/im-gateway/v1/media/server-media-id?mediaToken=..."
  }
}

客户端随后对 upload.url 执行二进制 PUT，再发送消息引用服务端返回的媒体对象。客户端不能把自己提供的下载 URL 交给服务端抓取。upload.maxBytes 由网关强制执行；当 sizeBytes 大于零时，上传字节数必须精确匹配，否则网关返回 400。

{

  "user": { "id": "u42", "name": "张三" },
  "message": {
    "type": "file",
    "text": "请阅读这份报告",

      "id": "server-media-id",

  }
}

同一服务端媒体也可以只传 id。小文件会作为内联附件交给 Agent 阅读或用于图片视觉理解；大文件会以服务端媒体 ID/URL 的形式出现在 Agent 上下文中。

5. 客户端工具执行扩展

这是面向工业控制、桌面自动化等接入场景的可选扩展，适用于连接中的客户端可以执行一小组白名单工具的情况。除非客户端在 /handshake 中声明 client_tools，否则不会启用。

{
  "capabilities": { "client_tools": true },
  "tools": [{
    "name": "plc.write_register",
    "risk": "write",
    "requiresApproval": true,
    "inputSchema": {
      "type": "object",
      "properties": {
        "address": { "type": "integer" },
        "value": { "type": "integer" }
      },
      "required": ["address", "value"]
    }
  }]
}

MaClaw 可能返回一次操作的 type: "tool_call"，也可能返回多步骤的 type: "tool_plan"。工具计划可使用 sequential、parallel、dag 或 interactive 模式。工业控制场景优先使用 sequential 或 dag；危险写操作应按步骤要求审批。

{
  "type": "tool_plan",
  "toolPlan": {
    "id": "tp_001",
    "mode": "sequential",
    "steps": [
      { "id": "step_1", "tool": "plc.read_register", "arguments": { "address": 40001 } },
      { "id": "step_2", "tool": "plc.write_register", "arguments": { "address": 40002, "valueFrom": "step_1.value" }, "dependsOn": ["step_1"], "requiresApproval": true }
    ]
  }
}

执行完成后必须调用 POST /tool-result 上报，并提供稳定的 resultId 或 idempotencyKey；status 可为 success、error、rejected、cancelled 或 timeout。/ack 只表示客户端收到了出站消息，不表示工具已完成。每个写类调用都应有 idempotencyKey、超时、审计记录和本地客户端策略检查。大型工具输出应复用服务端媒体流程，避免塞入过大的 JSON 载荷。

6. 字段约定

字段说明
clientId第三方软件实例的稳定唯一 ID。
conversationId第三方系统中的会话、客户、工单或群聊 ID。
eventId入站消息唯一 ID，用于重试幂等。
message.id / attachments[].id服务端媒体 ID，可作为唯一媒体引用。
message.data / attachments[].data小文件 base64 内容，必须小于 maxDirectBytes。
message.url / attachments[].url服务端提供的媒体下载 URL，客户端只访问它。
message.fileName / attachments[].fileName仅作为媒体元数据，不能替代 id、data 或服务端 url。
toolCall.idMaClaw 生成的唯一工具调用 ID。
toolCall.idempotencyKey客户端用于防止重复执行的稳定键。
tool-result.resultId / tool-result.idempotencyKey稳定的结果标识，重试时复用可避免重复注入 Agent 上下文。
toolPlan.steps[].dependsOndag 或受保护顺序执行中的步骤依赖列表。
cursor出站消息游标，客户端保存上一次返回值。

7. 请求追踪、错误和 ACK 语义

响应通常包含 requestId，排查问题时请一并提供。/outgoing 通过 cursor 提供至少一次投递，因此客户端需要按 message.id 去重。/ack 是第三方系统已把回复投递给自己的用户或业务系统后的送达回执，不替代客户端 cursor 持久化。

{
  "ok": false,
  "requestId": "gw_1760000000000000000",
  "error": {
    "code": "bad_request",
    "message": "clientId is required"
  }
}

MaClawSrv 和 MaClaw GUI 返回相同错误信封。请读取 error.code 和 error.message，不要依赖顶层 code 或 message 字段。

8. 测试客户端

$env:MACLAW_GATEWAY_TOKEN = "你的 Token"
go run ./cmd/connnectMaClaw -text "你好，确认第三方通道是否可用"

9. 错误处理

HTTP含义建议
400请求结构、字段或媒体引用无效检查 JSON、base64、附件大小和媒体 ID。
401缺少 Token 或 Token 无效检查 Authorization 请求头。
404媒体不存在或 mediaToken 无效重新请求上传 URL 或检查是否过期。
409重复事件或状态冲突将幂等重复视为成功，或刷新 cursor。
429请求过快指数退避后重试。
5xxMaClaw 处理失败保留同一个 eventId，稍后重试。

MaClaw Third-Party Software Access Protocol v1

Third-party software connects to the MaClaw HTTP gateway, sends user messages with JSON, and retrieves Agent replies through cursor-based long polling. The client does not need to expose public callback or file download URLs; MaClaw provides upload and download URLs for files.

Default endpoint http://127.0.0.1:18777/api/im-gateway/v1 Bearer Token Small files inline Large files by server URL

1. Integration Flow

  1. Open Settings / Message Access / Third-party Access in MaClaw.
  2. Configure Host, Port, and Token. The default listener is 127.0.0.1:18777.
  3. Call POST /handshake to discover capabilities, limits, and polling settings.
  4. For small files, send base64 data directly in POST /incoming.
  5. For large files, call POST /media/upload-url, upload bytes with the returned PUT URL, then reference the returned media.id or media.url in the message.
  6. Call GET /outgoing with a cursor to long-poll replies, then call POST /ack.

2. Authentication

Except for /health and media URLs protected by mediaToken, requests should include:

Authorization: Bearer <token>

Use Generate Token in MaClaw to create a strong random key. If it may have leaked, regenerate it and update the third-party configuration. The mediaToken inside upload/download URLs is generated by MaClaw; clients should only use those URLs, not construct them.

3. Capabilities and Limits

Protocol structs, validators, default limits, feature flags, strict JSON decoding, and handshake response construction are centralized in corelib/im. MaClawSrv and MaClaw GUI use the same core implementation, so a ThirdAPIDemo client sees the same protocol behavior from either endpoint. The handshake mode is maclaw for both server implementations.

/handshake returns these capabilities:

["text","image","file","voice","audio","attachments","server_media_upload","server_media_download","long_poll","ack","idempotency","client_tools","tool_call","tool_plan","tool_result","tool_cancel"]
LimitMeaning
maxTextCharsMaximum text message length.
maxMediaCaptionMaximum caption length for image, file, and voice messages.
maxAttachmentsMaximum attachments per message, currently 10.
maxDirectBytesMaximum bytes allowed in direct base64 data, currently 256 KiB. Larger files must use server media URLs.
maxBodyBytesMaximum JSON request body size, currently 16 MiB.
maxMediaBytesMaximum server-media upload size, currently 50 MiB for both MaClawSrv and MaClaw GUI.

5. Client Tool Execution Extension

This optional extension is for industrial control, desktop automation, and other integrations where the connected client can execute a small whitelist of tools. It is not enabled unless the client advertises client_tools during /handshake.

{
  "capabilities": { "client_tools": true },
  "tools": [{
    "name": "plc.write_register",
    "risk": "write",
    "requiresApproval": true,
    "inputSchema": {
      "type": "object",
      "properties": {
        "address": { "type": "integer" },
        "value": { "type": "integer" }
      },
      "required": ["address", "value"]
    }
  }]
}

MaClaw may return type: "tool_call" for one operation or type: "tool_plan" for multiple steps. Tool plans can use sequential, parallel, dag, or interactive mode. For industrial control, prefer sequential or dag; dangerous writes should require approval per step.

{
  "type": "tool_plan",
  "toolPlan": {
    "id": "tp_001",
    "mode": "sequential",
    "steps": [
      { "id": "step_1", "tool": "plc.read_register", "arguments": { "address": 40001 } },
      { "id": "step_2", "tool": "plc.write_register", "arguments": { "address": 40002, "valueFrom": "step_1.value" }, "dependsOn": ["step_1"], "requiresApproval": true }
    ]
  }
}

Execution completion must be reported to POST /tool-result with stable resultId or idempotencyKey, and status set to success, error, rejected, cancelled, or timeout. /ack only means the client received the outgoing message; it does not mean a tool completed. Every write-like call should have an idempotencyKey, timeout, audit record, and local client-side policy check. Large tool outputs should use the same server-owned media flow instead of large JSON payloads.

6. Field Contract

FieldDescription
clientIdStable unique ID for the third-party software instance.
conversationIdConversation, customer, ticket, or group ID from the third-party system.
eventIdUnique inbound message ID for retry idempotency.
message.id / attachments[].idServer media ID. It can be used as the only media reference.
message.data / attachments[].dataBase64 content for small files. Must be smaller than maxDirectBytes.
message.url / attachments[].urlServer-provided media download URL. Clients only access it.
message.fileName / attachments[].fileNameMedia metadata only. It does not replace id, data, or server url.
toolCall.idUnique tool call ID generated by MaClaw.
toolCall.idempotencyKeyStable key used by the client to prevent duplicate execution.
tool-result.resultId / tool-result.idempotencyKeyStable result identity. Reusing it on retry prevents duplicate Agent injection.
toolPlan.steps[].dependsOnStep dependency list for dag or guarded sequential execution.
cursorOutgoing message cursor. The client stores the last returned value.

7. Request Tracing, Errors, and ACK Semantics

Responses usually include requestId. Include it when reporting issues. /outgoing provides at-least-once delivery by cursor, so clients should deduplicate by message.id. /ack is a delivery receipt after the third-party system has delivered the reply to its user or business system; it does not replace client-side cursor persistence.

{
  "ok": false,
  "requestId": "gw_1760000000000000000",
  "error": {
    "code": "bad_request",
    "message": "clientId is required"
  }
}

MaClawSrv and MaClaw GUI return the same error envelope. Read error.code and error.message; do not depend on top-level code or message fields.
