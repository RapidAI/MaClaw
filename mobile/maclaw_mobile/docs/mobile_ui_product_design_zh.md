# MaClaw Mobile 界面与交互设计

## 1. 文档目的

本文定义 MaClaw Mobile 的移动端产品结构、页面职责和核心交互。设计参考 OpenClaw Android 的移动伴侣模式，但不复制其自托管 Gateway 配置流程。

MaClaw Mobile 的定位是：

> 用户通过手机号登录后，在手机上使用 MaClaw AI 助手，调用所属租户中的数字员工、远程服务器和电脑能力。

手机端负责快速表达意图、确认风险、查看结果；Hub、租户、Credits、数字员工运行时和远程设备连接由 MaClaw 官方服务管理。

参考资料：

- [OpenClaw Android README](https://github.com/openclaw/openclaw/blob/main/apps/android/README.md)
- [OpenClaw Android 官方文档](https://docs.openclaw.ai/android)
- [OpenClaw Google Play 页面](https://play.google.com/store/apps/details?id=ai.openclaw.app)

## 2. 设计原则

### 2.1 助手优先

登录并完成官方 LLM 配置后，直接进入 AI 助手，不先展示 HubCenter、服务器列表或后台配置。

### 2.2 移动端是控制面，不是桌面镜像

手机适合提出请求、语音输入、查看摘要、审批高风险操作和接收完成通知，不适合长时间盯住终端、复杂工作流或完整 Office 排版。

### 2.3 能力按任务组织

用户不需要理解 Hub、租户、Gateway、Worker 等内部概念。界面显示“助手”“员工”“文档”“设置”等用户目标，连接状态只在需要时解释。

### 2.4 风险透明且可控

涉及服务器、电脑、文件和高风险命令时，聊天消息中明确显示：目标、动作、影响、状态和确认按钮。未经用户确认，不执行高风险操作。

### 2.5 短时可用、随时可离开

每个任务都支持后台继续、通知回到结果、断线恢复和稍后查看。界面不要求用户持续停留。

### 2.6 官方服务默认，第三方可选

手机号登录后默认使用该账户绑定的 MaClaw 官方 Credits。第三方 LLM 只在设置中通过 MaClaw GUI 生成的二维码接入，不改变默认登录和首次使用路径。

## 3. 总体信息架构

```text
启动
  ├─ 未登录：手机号注册/登录
  ├─ 已登录但未配置官方 LLM：LLM 配置
  ├─ 已登录且服务可用：AI 助手
  └─ 已登录但服务异常：AI 助手 + 顶部连接状态提示

底部导航
  ├─ AI助手：主对话和多个副对话 Tab
  ├─ 员工：数字员工列表及员工专属对话
  ├─ 文档：应急文档生成、导入、编辑和导出
  └─ 设置：账户、LLM、通知、权限、缓存和服务状态

全局能力
  ├─ 语音输入
  ├─ 拍照/图片/文件输入
  ├─ 系统分享链接到 AI助手
  ├─ 任务通知
  ├─ 风险审批
  └─ Hub/租户连接恢复
```

“服务器”不作为首屏底部主导航。远程服务器维护既可以从 AI 助手发起，也可以从员工对话中调用；设置中只保留服务器连接状态和凭据管理入口。

## 4. 启动和登录流程

### 4.1 启动页

- 显示 MaClaw Logo 和短暂服务初始化状态。
- 检查本地手机号会话和官方服务状态。
- 不显示 HubCenter 候选地址。
- 不显示 Flutter 默认 Logo。

### 4.2 手机号登录/注册

1. 输入手机号。
2. 后台通过预置 HubCenter 地址探测可用 HubCenter。
3. HubCenter 解析用户所属 Hub 和租户。
4. 发送短信验证码。
5. 验证成功后：新手机号创建用户并登录，旧手机号直接登录。
6. 使用该手机号绑定的官方 Credits 调用 LLM。

界面要求：

- 用户只看到手机号、验证码、发送状态和错误恢复提示。
- HubCenter 探测过程显示为“正在连接 MaClaw 服务”，不暴露候选 URL。
- 验证码错误、过期、频率限制和网络失败必须有明确提示。
- 登录成功后恢复上一次主对话 Tab。

### 4.3 LLM 未配置流程

登录成功但没有可用 LLM 时显示简洁配置页：

1. 输入 MaClaw 官方服务兑换码。
2. 在设置中扫描 MaClaw GUI LLM 配置页生成的服务商二维码。

官方服务为默认主路径；二维码接入仅作为“其他 LLM”可选项，不能阻塞手机号登录。

## 5. AI 助手页面

### 5.1 页面职责

AI 助手是默认首页，承担：

- 查信息和联网搜索
- 资料总结和链接解析
- 调用数字员工
- 发起远程服务器/电脑维护
- 生成和编辑文档
- 接收图片、拍照、文件和语音
- 展示任务状态、审批请求和最终结果

### 5.2 页面结构

```text
AppBar
  左：当前会话标题 / 连接状态
  右：新建 Tab、会话菜单

Tab strip
  主对话 | 副对话 1 | 副对话 2 | +

Conversation
  用户消息
  AI 流式消息
  引用来源
  工具/数字员工任务卡
  审批卡片
  文档结果卡片

Composer
  附件 / 拍照 / 图片
  文本输入
  麦克风
  发送
```

### 5.3 多 Tab

- 保留“主对话”和副对话 Tab。
- 每个 Tab 独立保存消息、查询、引用和任务状态。
- 新建 Tab 默认不复制敏感凭据和未确认操作。
- Tab 标题由用户问题自动生成，也可以手动重命名。
- 后台任务完成后，通知点击直接回到对应 Tab。

### 5.4 输入方式

- 文本输入：支持多行、粘贴和发送中取消。
- 语音输入：按住或点击麦克风开始，实时把识别文本放回输入框，用户确认后发送。
- 拍照/图片：进入图片理解或文档处理流程。
- 文件：进入文档解析流程。
- 系统分享：登录前暂存，登录后自动交给助手处理。

### 5.5 AI 回复类型

AI 回复不能只有纯文本，至少支持以下消息类型：

- 普通回答
- 搜索回答 + 引用来源
- 任务执行中
- 等待用户审批
- 数字员工结果
- 文档草稿
- 服务器日志摘要
- 命令草案
- 失败及重试

## 6. 员工 Tab 与数字员工对话

### 6.1 员工列表

员工 Tab 显示当前租户可用的数字员工：

- 员工名称
- 能力简介
- 所属电脑/服务器
- 在线/离线状态
- 访问策略
- 是否需要拥有者确认

整张员工卡片可点击，点击后进入该员工专属聊天，而不是弹出一次性任务表单。

### 6.2 员工聊天

员工聊天沿用 AI 助手的消息体验，但增加员工身份信息：

- 顶部显示员工名称、能力和在线状态。
- 首条消息说明该员工能处理的任务类型。
- 输入框支持文字、语音、图片和文件。
- 每条请求通过所属 Hub 提交给选中的数字员工。
- 任务执行中显示状态，不伪造即时回答。
- 完成后以员工消息回填结果。
- 高风险操作显示审批卡片或命令草案。

### 6.3 员工对话和主助手的关系

- 员工聊天是独立会话，避免不同员工上下文混淆。
- 主助手可以建议调用某个员工，并通过员工聊天继续处理。
- 员工结果可以整理为文档草稿、复制或分享。
- 员工离线时仍可查看历史，但发送按钮应显示不可用原因。

## 7. 远程服务器和电脑能力

### 7.1 用户体验

用户在助手或员工聊天中直接表达需求，例如：

- “检查生产服务器最近的错误日志。”
- “查看办公室电脑上的报告并总结。”
- “重启服务，但先告诉我影响和回滚方式。”

系统将请求路由到所属 Hub、数字员工或后端 SSH 会话。手机不需要让用户手动理解底层连接拓扑。

### 7.2 状态卡片

远程任务卡片至少包含：

- 目标设备
- 当前数字员工或执行者
- 当前状态：排队、执行中、等待确认、完成、失败、离线
- 最近更新时间
- 查看详情、停止、重试或回到会话

### 7.3 风险审批

高风险操作必须显示确认卡片：

```text
操作：重启生产服务
目标：production-server-01
影响：可能造成约 1-3 分钟服务不可用
回滚：启动服务并检查健康状态

[拒绝] [查看命令] [确认执行]
```

默认只生成命令草案，不自动执行删除、重启、权限变更、批量修改等操作。

## 8. 文档页面

文档 Tab 面向应急场景：

- 从模板新建通知、报告、邮件、方案、会议纪要和说明书。
- 导入 Word、PDF、Excel、图片。
- 调用助手进行摘要、翻译、改写、扩写和格式整理。
- 提供轻量标题、段落、列表、表格和批注编辑。
- 导出 PDF、Word、Markdown 并调用系统分享。

复杂排版不在手机端复刻桌面 Office。文档任务采用和助手一致的任务卡、进度、失败重试和完成通知。

## 9. 设置页面

设置只承载低频配置，不承载主要工作流：

### 9.1 账户与服务

- 当前手机号
- 所属租户
- 官方 Credits 和用量
- Hub 服务状态
- 退出登录

### 9.2 LLM

- MaClaw 官方服务状态
- 官方兑换码
- 扫描 MaClaw GUI 服务商二维码
- 当前提供商和模型
- 清除第三方 LLM 配置

### 9.3 权限和通知

- 麦克风
- 相机
- 文件访问
- 本地通知
- 远程 Push（服务支持时显示）

### 9.4 数据和安全

- 清除会话和任务记录
- 清除文档草稿
- 清除服务器配置缓存
- 生物识别锁
- 敏感信息上传确认

## 10. 状态和错误设计

所有服务状态都使用用户可理解的文案：

| 内部状态 | 移动端表现 |
| --- | --- |
| Hub 探测中 | 正在连接 MaClaw 服务 |
| Hub 不可用 | 服务暂时不可用，稍后重试 |
| 会话过期 | 登录状态已过期，请重新验证手机号 |
| LLM 不可用 | 当前 AI 服务不可用，查看服务状态 |
| 员工离线 | 员工当前不在线，可查看历史或稍后重试 |
| 任务排队 | 已提交，等待远程设备处理 |
| 等待确认 | 需要你确认后才能继续 |
| 任务失败 | 显示原因、重试和复制诊断信息 |

不能把 HubCenter URL、租户内部 ID、原始 WebSocket 错误直接作为主要用户文案；调试信息可放在“查看详情”中。

## 11. 技术映射

| 设计能力 | Flutter 实现 |
| --- | --- |
| 页面导航 | GoRouter + 登录状态重定向 |
| 全局状态 | Riverpod |
| 网络请求 | Dio |
| 实时任务 | WebSocket / Mobile Realtime Bridge |
| 本地会话和草稿 | Drift / SQLite |
| Token 和敏感凭据 | flutter_secure_storage |
| 语音输入 | 现有 AssistantVoiceInput 抽象 |
| 数字员工聊天 | 复用 digital employee task API 和轮询/实时事件 |
| 任务通知 | 本地通知，服务支持时扩展 Push |
| 文档导出 | Hub 任务 + Flutter 系统分享 |

移动端不直接绑定桌面 Wails binding，也不在手机端运行完整数字员工运行时。远程执行仍由所属 Hub、GUI/Agent 或服务器端控制面完成。

## 12. 迭代计划

### Phase 1：核心助手

- 启动 Logo、手机号登录和官方 Credits
- AI 助手主 Tab 和副 Tab
- 流式回答、引用、语音输入、图片/文件入口
- Hub 连接状态和任务恢复

### Phase 2：数字员工

- 员工列表
- 员工专属聊天
- 任务状态和实时结果
- 高风险操作确认
- 员工结果整理为文档

### Phase 3：文档和远程维护

- 文档导入、编辑、导出
- 服务器/电脑维护任务卡
- 后端 SSH 会话状态和日志分析
- 任务完成通知和失败重试

### Phase 4：增强体验

- MaClaw GUI 二维码第三方 LLM 配置
- 系统分享入口
- 相机和截图理解
- 生物识别锁、弱网恢复、深色模式
- Android/iOS 真机适配和发布验收

## 13. 验收标准

- 登录成功后，配置完成的用户直接看到 AI 助手，不看到 HubCenter 候选地址。
- AI 助手支持主对话和副对话 Tab，能输入文字和语音。
- 员工 Tab 显示数字员工列表，点击员工进入聊天，而不是一次性表单。
- 员工消息通过真实 Hub 任务链路处理，处理中、等待确认、完成和失败状态可见。
- 高风险服务器/电脑操作默认不自动执行。
- 文档和远程维护结果可以从聊天消息继续处理、导出或分享。
- 断线、任务完成和服务异常均有明确恢复路径。
- 第三方 LLM 只在设置中配置，不影响官方 Credits 默认路径。
