# MaClaw Mobile

An Android/iOS Flutter app for emergency AI work:

- information lookup with sources;
- urgent document drafting, editing, and export;
- manual SSH server maintenance with AI-assisted log explanation;
- digital employee access for remote server or desktop capabilities;
- Hub account, quota, service status, cache, and credential management.

The app connects only to the official MaClaw service and does not expose custom
Hub endpoint configuration. It does not depend on the desktop Wails GUI.

Mobile keeps lightweight local cache for search history, server metadata,
common commands, digital employee prompts, and the most recent document draft.
Sensitive tokens and SSH credentials stay in secure storage.

## Commands

```bash
flutter pub get
flutter test
flutter run
```

Generate native wrappers if needed:

```bash
flutter create --platforms android,ios .
python3 tool/configure_platforms.py
```

## Native sharing

Android share/deep-link intent filters are generated into
`android/app/src/main/AndroidManifest.xml`.

iOS needs a real Share Extension target in the official Apple developer team:

- bundle id: `top.mypapers.maclaw.mobile.ShareExtension`;
- app group: `group.top.mypapers.maclaw.mobile`;
- target files generated by `tool/configure_platforms.py` under
  `ios/ShareExtension/`;
- Runner URL schemes: `maclaw` and `ShareMedia-$(PRODUCT_BUNDLE_IDENTIFIER)`;
- Runner and Share Extension entitlements must both include
  `$(CUSTOM_GROUP_ID)`.

The script generates the extension plist, entitlements, and
`ShareViewController.swift` that inherits `RSIShareViewController` from
`receive_sharing_intent`. Xcode still owns the signed target because Team ID and
provisioning profiles are official-service release settings.

## Hub persistence

Official Hub deployments should set `MACLAW_MOBILE_STATE_PATH` to a writable
JSON file path so mobile document drafts, upload/export jobs, and digital
employee tasks survive process restarts.
