# 数字员工中心：通讯与经验共享机制草案 v1

## 1. 定位

数字员工中心不是普通后台，也不只是一个配置中心。

它是企业内部数字员工的：
- 通讯中枢
- 经验交流中心
- 能力共享中心
- 模型调度中心
- 安全规则中心

### 一句话定义
**数字员工中心，是数字员工之间交流经验、共享能力、开展协作的中心。**

### 对内作用
- 让不同数字员工可以彼此协作
- 让优秀经验能够沉淀和复用
- 让“会做的事”可以集中管理和共享
- 让模型、安全和规则统一管理与下发

### 对外角色
对于 DiWorker 客户端来说，数字员工中心是：
- 同事列表来源
- 会做的事来源
- 配置和规则来源
- 协作与经验共享来源

---

## 2. 与 DiWorker / hubcenter 的关系

### DiWorker
面向普通用户，用于：
- 选择数字化同事
- 发起任务
- 查看结果
- 查看历史任务

### hubcenter
作为外部来源，用于：
- 搜索新的能力包
- 下载新的能力包
- 提供官方或第三方能力来源

### 数字员工中心
作为企业内部中枢，用于：
- 管理数字员工
- 管理能力包
- 管理经验共享
- 协调数字员工之间的协作
- 管理模型调度
- 管理安全规则
- 向 DiWorker 下发配置

### 关系示意
```text
hubcenter / 外部来源
        ↓
数字员工中心（审核 / 安装 / 共享 / 下发 / 通讯）
        ↓
DiWorker 客户端
        ↓
用户与数字员工协作完成任务
```

---

## 3. 核心目标

数字员工中心需要解决四类问题：

### 3.1 员工之间如何协作
一个数字员工接到任务后，如何把子任务交给另一个数字员工处理。

### 3.2 员工之间如何交流经验
一个数字员工积累的高质量处理方式，如何供其他数字员工参考和学习。

### 3.3 员工之间如何共享能力
一个数字员工新增的“会做的事”，如何授权其他数字员工使用。

### 3.4 如何统一控制模型与安全
多模型调用、安全规则和配置如何集中管理，并向客户端下发。

---

## 4. 四大机制

## 4.1 员工通讯机制

数字员工之间不应直接无规则通信，而应通过数字员工中心完成。

### 目标
让不同数字员工可以：
- 发起协作请求
- 请求某项能力支持
- 转交任务片段
- 返回处理结果
- 共享中间结论

### 数字员工注册自己的工作能力偏好
每个数字员工在数字员工中心中，除基础资料外，还应注册自己的工作能力偏好，例如：
- 更偏好的任务类型
- 更偏好的输出形式
- 更偏好的协作方式
- 更适合接收哪些委托
- 更适合委托给哪些员工类型

这些偏好用于：
- 提升任务匹配准确性
- 辅助协作推荐
- 减少无效委托

### 典型例子
- 小迪接到“月报汇总”任务
- 小迪将数据整理子任务发给阿宁
- 阿宁处理后返回数据摘要和图表建议
- 小迪整合为最终汇报材料

### 通讯原则
- 通讯要结构化
- 通讯要可审计
- 通讯要受权限控制
- 通讯要与任务上下文关联
- 协作任务必须体现在受托员工任务列表中

### 受托任务列表需要展示
- 由哪个员工委托
- 所属任务
- 当前状态
- 请求内容摘要
- 发起时间

### 状态建议
- 待命
- 拒绝
- 正在执行
- 完成

### 建议通讯字段
- 发起方员工
- 接收方员工
- 委托来源员工
- 任务 ID
- 请求类型
- 请求内容
- 相关附件 / 上下文
- 返回结果
- 状态
- 时间

### 请求类型示例
- 协助处理
- 请求分析
- 请求补充结果
- 借用能力
- 共享经验参考

## 4.2 经验共享机制

数字员工完成任务过程中形成的高质量做法，不应只停留在单次任务里，而应沉淀为经验。

### 定义
经验是数字员工在处理某类任务时形成的可复用做法。

### 经验可能包括
- 任务拆解方式
- 提问方式
- 输出结构
- 文案模板
- 常见问题及应对策略
- 高质量示例

### 经验共享目标
- 提升数字员工整体质量
- 缩短新员工适应时间
- 形成企业内部最佳实践

### 经验层级建议
- 私有经验：仅当前数字员工可用
- 团队经验：部分数字员工可共享
- 企业经验：全局可共享

### 经验流转过程
1. 任务执行形成经验候选
2. 经验进入沉淀区
3. 审核或确认
4. 发布为可共享经验
5. 其他数字员工可引用或学习

### 经验共享示例
- 老陈在“生产异常日报”形成高质量写法
- 小周可引用该经验处理质量问题说明
- 阿宁可学习该经验中的结构化表达方式

---

## 4.3 能力共享机制

对外不要强调 skill，对管理端建议使用：

## **能力包**

能力包是“会做的事”的可管理、可共享载体。

### 能力包来源
- hubcenter 搜索下载
- 企业内部上传
- 平台官方预置
- 从经验沉淀转化而来

### 能力包支持的动作
- 搜索
- 下载
- 安装
- 审核
- 绑定到某位数字员工
- 授权多个数字员工共享使用
- 更新版本
- 停用 / 下架

### 能力包示例
- 会议纪要能力包
- 异常上报能力包
- 生产日报能力包
- 质量分析能力包
- 数据汇总能力包
- 汇报摘要能力包

### 能力共享示例
- 阿宁新增“图表摘要能力包”
- 小迪可借用该能力包优化月报输出
- 小周可在质量分析报告中复用图表摘要能力

---

## 4.4 协作规则与安全机制

数字员工之间可以交流和协作，但不能无边界。

### 必须控制的内容
- 哪些数字员工可以互相通信
- 哪些经验可以共享
- 哪些能力包可以借用
- 哪些数据不可跨员工传递
- 哪些任务必须人工确认
- 哪些结果不允许自动外发

### 规则建议维度
- 按员工类型
- 按部门
- 按任务类型
- 按数据敏感级别
- 按能力包来源

### 必要能力
- 权限控制
- 内容审计
- 规则版本管理
- 灰度发布
- 生效范围配置

---

## 5. 模型调度中心

数字员工中心应统一管理多模型 API，并支持智能调度。

### 目标
- 不同数字员工可使用不同模型策略
- 不同任务类型可走不同模型
- 故障时可自动切换备用模型
- 成本、速度、质量可做平衡

### 可按任务类型调度
- 文档写作
- 数据分析
- 表格整理
- 图像理解
- 语音转写
- 长文本总结
- 生产异常分析

### 可按员工类型调度
- 办公同事优先文档能力强的模型
- 数据同事优先结构化分析强的模型
- 生产同事优先响应快、输出直接的模型
- 质量同事优先因果分析和建议能力强的模型

### 建议支持
- 默认模型
- 备用模型
- 按任务路由
- 按数字员工路由
- 调用审计
- 成本统计

## 8. 建议的协作流程

### 任务协作流程
1. 用户在 DiWorker 中把任务交给某位数字员工
2. 该员工在需要时向数字员工中心发起协作请求
3. 中心根据规则、能力和模型策略选择可协作对象
4. 目标员工处理子任务并返回结果
5. 发起员工整合结果并交付给用户
6. 优秀处理方式可沉淀为经验

### 能力获取流程
1. 管理员从 hubcenter 搜索能力包
2. 下载到数字员工中心
3. 审核和分类
4. 绑定给某位或多位数字员工
5. 下发给客户端使用

### 经验共享流程
1. 数字员工在任务中形成经验候选
2. 经验进入沉淀区
3. 审核后发布
4. 其他数字员工可学习或引用

## 9. 安全边界建议

### 原则
- 通讯必须可控
- 能力共享必须可审计
- 经验共享必须分级
- 外部来源必须审核
- 客户端尽量轻，复杂控制放中心
- IM 接入必须适配内网部署前提，不能假设可向公网暴露回调 URL

### IM 接入特别约束（飞书 / 钉钉 / 企业微信）
数字员工中心需要支持通过飞书 / 钉钉 / 企业微信接入，但应注意：
- 本系统可能仅部署于企业内网
- 不能默认依赖公网可访问 webhook 回调地址
- 不能直接照搬现有 hub 的公网暴露式接入方式

因此建议采用两类模式：

#### 模式 A：企业已有内外网网关 / 反向代理
若企业已有统一出口网关，可由网关暴露极小范围的回调入口，再反向转发到内网中的数字员工中心。

#### 模式 B：外部连接器 / 适配器
在可联网区域部署轻量连接器，负责：
- 接收飞书 / 钉钉 / 企业微信事件
- 与数字员工中心建立出站长连接或受控轮询
- 将消息转发回内网中心

对于仅内网部署场景，优先建议模式 B，而不是要求数字员工中心直接暴露公网 URL。

### 必须保留的控制
- 通讯白名单 / 黑名单
- 能力包来源审核
- 经验共享范围控制
- 敏感任务隔离
- 审批后外发
- 规则版本化

## 11. 总结

数字员工中心不只是一个管理后台，而应是：

- 数字员工的通讯中心
- 数字员工的经验中心
- 数字员工的能力共享中心
- 数字员工的模型与安全中枢

它的核心价值在于：
**让企业里的数字员工不再各自为战，而是像一个真正的数字团队一样协作、交流和成长。**
