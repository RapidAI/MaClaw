# 数字员工中心：V1 集成测试与事务回滚用例清单

## 1. 目标

本文件用于把前面的状态机、事务边界、开发切片、错误码设计，收敛成可以直接进入测试实现的用例清单。

重点覆盖：
- 主链路成功场景
- 关键失败场景
- 事务回滚场景
- 状态机非法流转场景
- 审计/事件落库场景

本文件优先服务：
- 后端集成测试
- service 层事务测试
- 联调前回归检查

---

## 2. 测试设计原则

### 2.1 优先验证主链路原子性
比起先堆大量查询接口测试，V1 更应优先验证：
- 该成功时是否完整落库
- 该失败时是否彻底回滚
- 状态是否一致
- 事件是否完整

### 2.2 一个用例至少验证三件事
建议每个核心用例都至少校验：
1. 接口返回
2. 主表状态
3. 事件/关联表状态

### 2.3 非法状态流转必须显式测试
例如：
- 已完成任务再次 complete
- standby 任务直接 complete
- completed 步骤再次 reject

### 2.4 外部依赖失败要有稳定断言
像：
- hubcenter 拉取失败
- provider 调用失败
- 安全引擎异常

都要验证系统对外语义和本地落库结果。

---

## 3. 推荐测试分层

建议分 4 层：

1. repo 基础持久化测试
2. service 事务/状态机测试
3. handler/API 集成测试
4. 主链路 E2E 测试

V1 最先补齐的是 2、3、4 层。

## 7. collaboration 模块测试用例

## 7.1 创建协作任务成功

### 前置
- `from -> to` 权限允许
- 安全规则允许

### 步骤

- 返回成功
- `communication_messages` 新增 1 条
- `status=standby`
- `communication_message_events` 新增 `created` 事件

### 步骤
- 调创建接口

### 断言
- HTTP `403`
- 错误码 `1300002`
- `communication_messages` 不新增
- `communication_message_events` 不新增

## 7.3 安全规则拒绝时不创建正式任务

### 前置
- security 返回 blocked

### 步骤

### 断言
- HTTP `403`
- 错误码 `1300003` 或安全模块对应错误
- `communication_messages` 不新增

## 7.4 standby 接受成功

### 步骤

## 7.5 accepted 开始成功

### 前置
- 已有 `accepted` 任务

### 步骤
- 调 start

### 断言

- 事件表新增 `started`

## 7.6 processing 完成成功

### 前置
- 已有 `processing` 任务

### 步骤
- 调 complete

### 断言
- 主记录状态变 `completed`
- `result_summary` / `result_payload_ref` 已更新

## 7.7 非法流转：standby 直接 complete

## 9. workflows 模块测试用例

## 9.1 创建流程实例并生成首步成功

- 三张运行态表均不新增

## 9.3 首步不可分配失败

### 步骤

### 断言
- 返回错误
- 错误码 `1400005` 或相关权限错误
- `workflow_instances` 不新增

- `communication_messages` 不新增

## 9.4 单步流程完成后实例 completed

### 前置
- 已创建单步流程实例
- 当前步骤/任务已推进到 processing

### 步骤
- 调 `POST /runtime/workflows/steps/{id}/complete`

### 断言
- 当前步骤变 `completed`
- 当前任务变 `completed`
- 实例变 `completed`
- 写入 `workflow_instance_events(completed)`

## 9.5 两步流程完成首步后生成下一步

### 前置
- 两步流程实例已创建
- 当前首步为 processing

### 步骤
- 调 complete

### 断言
- 当前步骤 completed
- 当前任务 completed
- 新增下一条 `workflow_step_instances(status=standby)`
- 新增下一条 `communication_messages(status=standby)`
- 新步骤 `delegation_message_id` 已回填
- `workflow_instances.current_step_id` 指向新步骤
- 写入 `step_advanced` 事件

## 9.6 步骤拒绝导致流程 rejected

### 前置
- 当前步骤状态为 standby/accepted/processing 之一

### 步骤
- 调 `POST /runtime/workflows/steps/{id}/reject`

### 断言
- 当前步骤 `rejected`
- 关联任务 `rejected`
- 实例 `rejected`
- 写入 `workflow_instance_events(rejected)`

## 9.7 非法流转：已完成步骤再次 reject

### 前置
- 当前步骤为 `completed`

### 步骤
- 调 reject

### 断言
- HTTP `409`
- 错误码 `1400006`

- 不新增事件

## 15. 错误码与返回结构检查用例

建议为每个模块至少补 1~2 个用例专门检查：
- HTTP 状态是否符合约定
- `code` 是否稳定
- `error.type` / `error.reason` 是否正确
- `request_id` 是否存在

重点检查：
- `1100001`
- `1200005`
- `1300004`
- `1400005`
- `1400007`
- `1500003`
- `1600002`
- `1700003`

## 16. 推荐测试实现顺序

建议按下面顺序补测试：

1. collaboration 成功/回滚测试
2. workflow 创建实例成功/回滚测试
3. workflow 步骤推进成功/回滚测试
4. configsync 发布成功/回滚测试
5. capabilities 导入/绑定测试
6. proxy 审计测试
7. colleagues 与通用错误码测试

原因：
- 事务风险最高的链路先补测试
- 越早发现原子性问题，越少返工

## 18. 一句话总结

**V1 的测试重点不应停留在“接口能调通”，而应集中验证“主记录、状态、事件、关联关系、回滚行为”是否在成功与失败两侧都保持一致，这才是数字员工中心主链路可上线的关键。**
